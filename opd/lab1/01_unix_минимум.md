# 01. Минимум UNIX для лабы

Все команды пробуй **на helios**. На маке тоже есть терминал, но macOS и helios (FreeBSD) в мелочах отличаются, а сдавать на helios.

```bash
ssh -p 2222 s561306@helios.cs.ifmo.ru     # зайти
bash                                      # если приглашение не похоже на [s561306@helios ~]$ — включить bash
mkdir ~/sandbox && cd ~/sandbox           # песочница для упражнений, потом удалишь: rm -rf ~/sandbox
```

## 1. Файловая система и пути
- Всё начинается с корня `/`. Твоя домашняя папка `~` — это `/home/studs/s561306`.
- **Абсолютный путь** начинается с `/`: `/home/studs/s561306/lab0/bagon`.
- **Относительный путь** считается от текущей папки: `lab0/bagon`, `../bagon`.
- `.` — текущая папка, `..` — родительская.

| Команда | Что делает |
|---|---|
| `pwd` | показать, где я |
| `cd путь` | перейти (`cd` без аргументов — домой, `cd ..` — на уровень выше) |
| `ls` | список файлов; `-l` подробно, `-a` скрытые, `-R` рекурсивно |
| `mkdir a b c` | создать папки; `mkdir -p a/b/c` создаст сразу всю цепочку |
| `touch f` | создать пустой файл (или обновить время) |
| `echo "текст"` | напечатать текст |
| `cat f1 f2` | вывести файлы подряд (con**cat**enate); `-n` — с номерами строк |
| `more f` | постраничный просмотр (выход — `q`) |
| `cp src dst` | копировать; `cp -r` — папку целиком |
| `mv src dst` | переместить или переименовать |
| `rm f` | удалить файл; `-r` — папку с содержимым; `-f` — без вопросов |
| `rmdir d` | удалить **пустую** папку |

✏️ **Упр. 1.** В песочнице создай `a/b/c` одной командой, перейди в `c`, выведи `pwd`, вернись в песочницу через `cd ../../..`.

## 2. Перенаправление потоков
У каждой программы три стандартных потока:

| № | Имя | Куда по умолчанию |
|---|---|---|
| 0 | `stdin` — ввод | клавиатура |
| 1 | `stdout` — вывод | экран |
| 2 | `stderr` — ошибки | экран |

| Запись | Смысл |
|---|---|
| `cmd > f` | stdout в файл (файл **перезаписывается**) |
| `cmd >> f` | stdout **дописать** в конец файла |
| `cmd 2> f` | stderr в файл |
| `cmd 2>> f` | stderr дописать в файл |
| `cmd 2>&1` | stderr туда же, куда stdout («добавить ошибки в стандартный вывод») |
| `cmd 2>/dev/null` | ошибки выбросить |
| `cmd < f` | stdin из файла |
| `cmd1 \| cmd2` | **конвейер**: stdout первой команды идёт на stdin второй |

```bash
echo "первая строка" > f.txt      # создать файл с одной строкой
echo "вторая строка" >> f.txt     # дописать вторую
cat f.txt
ls nope 2> /tmp/err_$USER          # ошибка «нет такого файла» уйдёт в файл
cat /tmp/err_$USER
```
⚠️ Порядок важен: в `cmd 2>&1 | grep x` ошибки попадут в конвейер вместе с выводом, а в `cmd | grep x 2>&1` — нет, потому что `2>&1` там относится к `grep`.

✏️ **Упр. 2.** Выполни `ls . nope`. Потом ту же команду, но так, чтобы на экране осталось только имя текущего содержимого, а ошибка ушла в `/tmp/err_$USER`.

## 3. Фильтры: `grep`, `sort`, `head`, `tail`, `wc`
**Фильтр** — команда, которая читает stdin, как-то его преобразует и пишет в stdout. Их удобно соединять конвейером.

| Команда | Главные ключи |
|---|---|
| `grep шаблон` | оставить строки с шаблоном; `-v` — наоборот, без него; `-i` — без учёта регистра; `-n` — номера строк |
| `sort` | по алфавиту; `-r` — обратный порядок; `-n` — как числа; `-k5` — по 5-му столбцу |
| `head -n 3` | первые 3 строки |
| `tail -n 2` | последние 2 строки |
| `wc` | `-l` строки, `-w` слова, `-c` байты, `-m` **символы** (для русских букв это важно: одна буква — 2 байта, но 1 символ) |

Мини-регулярки для grep: `^a` — строка начинается на a, `a$` — заканчивается на a, `.` — любой символ.

```bash
ls -l /etc | grep "conf$" | sort -k5 -n | tail -n 3
# список /etc → только строки, оканчивающиеся на conf → сортировка по размеру (5-й столбец) → последние 3
```

✏️ **Упр. 3.** Создай файл с 5 строками разной длины (`echo ... >>`). Выведи его с номерами строк (`cat -n`), оставь только строки со словом, которое есть в двух из них (`grep`), и отсортируй их в обратном порядке.

✏️ **Упр. 4.** Сравни `echo "привет" | wc -c` и `echo "привет" | wc -m`. Почему числа разные? (Если вдруг совпали, значит в сессии не UTF-8 локаль: проверь `locale`.)

## 4. `ls -l`: как читать вывод
```
-rw-r--r--  1 s561306 studs  183 Sep 28 12:00 zoroark
│└┬┘└┬┘└┬┘  │    │       │     │       │         └ имя
│ │  │  │   │    │       │     │       └ дата изменения
│ │  │  │   │    │       │     └ размер в байтах
│ │  │  │   │    │       └ группа-владелец
│ │  │  │   │    └ владелец
│ │  │  │   └ число жёстких ссылок
│ │  │  └ права остальных (o)
│ │  └ права группы (g)
│ └ права владельца (u)
└ тип: - файл, d каталог, l символическая ссылка
```
Полезные ключи: `-t` сортировка по времени (новые сверху), `-c` использовать время **изменения записи о файле** (ctime, меняется в том числе от chmod), `-S` по размеру (большие сверху), `-r` обратный порядок, `-R` рекурсивно.

## 5. Права доступа
Три группы пользователей: **u** — владелец (user), **g** — группа (group), **o** — остальные (others). Три права: **r** (read), **w** (write), **x** (execute).

| | Для файла | Для каталога |
|---|---|---|
| **r** | читать содержимое | **видеть список** файлов (`ls`, работа шаблонов `*`) |
| **w** | изменять | **создавать, удалять, переименовывать** файлы внутри (нужен ещё x) |
| **x** | запускать как программу | **заходить** (`cd`) и обращаться к файлам внутри по имени |

⚠️ Главная ловушка лабы: удалить или создать файл — это изменить **каталог**, в котором он лежит. Права самого файла тут вторичны.

### Два способа задать права
**Числовой (восьмеричный):** r = 4, w = 2, x = 1, складываем внутри каждой тройки.
```
rw- r-- r--  →  6 4 4  →  chmod 644 f
rwx r-x --x  →  7 5 1  →  chmod 751 d
```
**Символьный:** `кому` `+ − =` `что`.
```bash
chmod u+x f          # владельцу добавить x
chmod go-w f         # группе и остальным убрать w
chmod u=rw,g=r,o= f  # точно задать все три тройки (o= — ничего)
chmod a=r f          # всем (all) только чтение
```
В лабе нужно использовать **оба способа** («различные способы указания прав»), поэтому в скрипте чередуй их.

✏️ **Упр. 5.** Переведи сам: `rwxr-x---`, `-wxr-xrwx`, `r--r-----`, `------r--`. Ответы в конце файла.

✏️ **Упр. 6.** Создай папку `d` с файлом `d/f`. Сделай `chmod u-r d` и попробуй `ls d`, потом `cat d/f`. Затем `chmod u-x d` и снова `cat d/f`. Объясни, что произошло. Не забудь вернуть права: `chmod u+rwx d`.

## 6. Ссылки
**Жёсткая ссылка** `ln target name` — второе имя для **того же самого** файла (того же inode). Удалишь одно имя, файл останется доступен по другому. Число в 2-м столбце `ls -l` — сколько у файла имён. На каталоги жёсткие ссылки делать нельзя.

**Символическая ссылка** `ln -s target name` — маленький файл-указатель с путём внутри (как ярлык). Если удалить цель, ссылка «повиснет». В `ls -l` видна как `l... name -> target`.

⚠️ Путь цели в `ln -s` считается **от папки, где лежит ссылка**, а не от текущей:
```bash
cd ~/lab0
ln -s ../bagon pansear/raltsbagon   # ссылка лежит в pansear, поэтому до bagon — «../bagon»
ln -s bagon pansear/raltsbagon      # НЕВЕРНО: ссылка будет искать pansear/bagon
```

✏️ **Упр. 7.** Создай файл `x`, жёсткую ссылку `xh` и символическую `xs`. Посмотри `ls -li` (i — номер inode). Удали `x` и проверь, что показывает `cat xh` и `cat xs`.

## 7. Шаблоны имён (glob)
`*` — любая строка, `?` — один символ. Шаблоны раскрывает **shell** до запуска команды:
```bash
ls *t          # всё в текущей папке, что заканчивается на t
cat */*t       # файлы на t на один уровень глубже
rm Copy_*      # всё, что начинается с Copy_
```
⚠️ Если у папки нет права **r**, shell не может прочитать список её файлов, и шаблон `папка/*` **не раскроется**: команда получит буквальную строку `папка/*` и напишет «No such file or directory».

## 8. Скрипт
Методичка требует записать все команды в файл, по одной на строку, чтобы работу можно было повторить автоматически.
```bash
nano lab0.sh          # или vi; в nano сохранение — Ctrl+O, выход — Ctrl+X
bash lab0.sh          # запуск
```
Первая строка скрипта: `#!/bin/bash`, комментарии начинаются с `#`.

Удобнее писать скрипт на маке в IntelliJ или любом редакторе и копировать на helios: `scp -P 2222 lab0.sh s561306@helios.cs.ifmo.ru:~/`.
