## 0. Операционная система

### Что такое ОС
- Исторически ОС появилась, чтобы **заменить работу оператора** ЭВМ: раньше человек вручную загружал программы, переключал задания, следил за устройствами. Теперь это делает программа.
- ОС — комплекс программ, который **управляет ресурсами** компьютера (процессор, память, диски, устройства) и даёт программам и пользователю **удобный интерфейс** к ним.
- Условно ОС делят на **пользовательские** (Windows, macOS, Linux на десктопе), **серверные** (Linux, FreeBSD, Solaris), **встроенные** (VxWorks, Embedded Linux, когда-то DOS). Отдельно стоят **мобильные** (Android, iOS) и **гипервизоры** (запускают другие ОС).
- Обычно ОС включает **ядро** с подсистемами управления памятью и процессами и **драйверы устройств**, а вокруг — системные утилиты и оболочку (shell).

### История UNIX
- **1969**, Bell Labs (AT&T): Кен Томпсон и Деннис Ритчи пишут UNIX. В **1973** ядро переписано на языке **C**, который Ритчи для этого и придумал. Благодаря этому UNIX легко переносился на разные машины.
- Дальше две главные ветки:
  - **System V** (коммерческий UNIX от AT&T): Solaris, AIX, HP-UX.
  - **BSD** (Berkeley Software Distribution, Калифорнийский университет в Беркли): FreeBSD, NetBSD, OpenBSD, а также macOS (её ядро Darwin частично из BSD).
- **1991**: Линус Торвальдс пишет ядро **Linux**. Linux — не потомок кода UNIX, а «UNIX-подобная» система, написанная заново. Вместе с утилитами проекта **GNU** даёт полноценную ОС. Дистрибутивы: RedHat, Fedora, Debian, Ubuntu, SUSE, Arch, Gentoo.
- **POSIX** — стандарт, который описывает, как должна вести себя UNIX-подобная система (системные вызовы, shell, базовые утилиты). Благодаря ему команды из лабы почти одинаково работают на FreeBSD, Linux и macOS.
- **helios** работает на **FreeBSD**, то есть ветка BSD. Поэтому некоторые ключи там отличаются от Linux (GNU): например, `ls --color` или `grep --include` могут не сработать, а `man` покажет BSD-версию.

### Ядро *NIX (слайд «Ядро *NIX»)
```
  Пользовательские процессы:  bash   ls   sort   grep   LibreOffice ...
                              (у каждого своя память: code, data, stack)
  ─────────────────────── Интерфейс системных вызовов ───────────────────────
  Ядро:   Управление памятью │ Управление процессами и потоками │
          Виртуальная файловая система (VFS) │ Сетевая подсистема
          Драйверы устройств │ Платформо-зависимый код
  ─────────────────────────────────── Железо ───────────────────────────────
```
- **Пользовательский режим и режим ядра.** Обычная программа не может напрямую трогать диск или чужую память. Она просит ядро через **системный вызов** (`open`, `read`, `write`, `fork`, `exec`, `chmod`, `unlink`...). Каждая команда из лабы внутри — это несколько системных вызовов. Например, `rm f` вызывает `unlink("f")`, `chmod 644 f` — `chmod("f", 0644)`, `ln a b` — `link("a","b")`, `ln -s a b` — `symlink("a","b")`.
- **Управление памятью:** каждому процессу выделяется своё виртуальное адресное пространство, процессы не видят память друг друга.
- **Управление процессами и потоками:** планировщик решает, какой процесс сейчас выполняется на процессоре; создание и завершение процессов.
- **VFS (виртуальная файловая система):** единый интерфейс к разным файловым системам (UFS, ZFS, ext4, сетевые, `/proc`, `/dev`). Именно благодаря VFS «всё есть файл».
- **Сетевая подсистема:** TCP/IP, сокеты.
- **Драйверы:** код для работы с конкретными устройствами.
- **Платформо-зависимый код:** то, что разное для x86, ARM и т. д.

### Процесс
- **Программа** — файл на диске. **Процесс** — программа в момент выполнения: код + данные + стек + открытые файлы + права + текущий каталог.
- Память процесса (на слайдах): **code** (машинный код), **data** (глобальные данные, куча), **stack** (локальные переменные, адреса возврата).
- У процесса есть **PID** (номер), **PPID** (номер родителя), **владелец** (UID) и **группа** (GID). Права доступа к файлам проверяются именно по UID/GID процесса.
- Новый процесс создаётся вызовом **`fork`** (копия родителя), потом **`exec`** заменяет код на другую программу. Так shell запускает каждую команду: `fork`, в дочернем процессе настраивает потоки (перенаправления!), затем `exec ls`.
- Каждый процесс при завершении возвращает **код возврата** (exit status): `0` — успех, не ноль — ошибка. В shell его видно через `echo $?`.

```bash
ps            # мои процессы
ps -ax        # все процессы (на FreeBSD ключи как в BSD)
echo $$       # PID текущего shell
ls nope; echo $?    # не 0, потому что файла нет
ls .; echo $?       # 0
```

## 1. Пользователи и группы
- Каждый пользователь имеет **имя** (`s561306`) и числовой **UID**. Ядро работает с числами, имена хранятся в `/etc/passwd`.
- Пользователь состоит в одной основной группе и, возможно, в дополнительных. На helios основная группа студентов — **`studs`**.
- **root** (UID 0) — суперпользователь, для него права доступа **не проверяются** (почти: `x` для запуска нужен хотя бы у кого-то).
- Каждый файл принадлежит одному **владельцу** и одной **группе-владельцу**. Новый файл получает владельцем того, кто его создал.

```bash
whoami        # имя
id            # uid, gid и все группы
groups        # список групп
ls -ln        # ls -l, но вместо имён владельца и группы — числа UID и GID
```

**Как ядро проверяет доступ** (важно для понимания всех ошибок лабы): если ты владелец файла, смотрятся **только** права владельца (u). Иначе, если ты в группе файла, — **только** права группы (g). Иначе — права остальных (o). Права не складываются! Пример: у `bagon` права `004` (`------r--`). Остальные могут читать, а ты, владелец, **не можешь**, хотя «остальным» можно. Именно поэтому в п. 3 понадобился `chmod u+r bagon`.

## 2. Shell (командный интерпретатор)

### Что это
- **Shell** — обычная программа (процесс), которая читает команды, разбирает их и запускает другие программы. Это интерфейс между пользователем и ОС.
- Виды: **sh** (Bourne shell, классика, есть везде), **ksh** (Korn shell), **csh** / **tcsh** (C shell, синтаксис похож на C; на FreeBSD бывает у пользователей по умолчанию), **bash** (Bourne-again shell, расширенный sh, стандарт в Linux), **zsh** (по умолчанию на macOS).
- Узнать свой: `echo $SHELL` (shell при входе), `ps -p $$` (текущий).
- Скрипты лабы начинаются с `#!/bin/sh`, значит их выполняет sh. Синтаксис перенаправлений в sh и bash одинаковый, а в csh другой (`>&` вместо `2>&1`), поэтому на helios лучше работать в bash или sh.

### Что делает shell с каждой строкой (по порядку)
1. Делит строку на **слова** по пробелам (с учётом кавычек).
2. Подставляет **переменные** (`$HOME`, `$USER`) и результаты команд (`$(cmd)`).
3. Раскрывает **шаблоны** (`*`, `?`, `[...]`) в список имён файлов.
4. Разбирает **перенаправления** (`>`, `2>`, `|`...) и убирает их из списка аргументов. Программа **не видит** `> f` в своих аргументах.
5. Ищет программу (встроенная команда или файл в каталогах из `$PATH`), делает `fork` + `exec`.
6. Ждёт завершения и запоминает код возврата в `$?`.

Отсюда важный вывод для защиты: `*` раскрывает **shell**, а не `ls` или `rm`. Перенаправления тоже делает **shell**, а не команда.

### Встроенные и внешние команды
- **Встроенные** (builtin) выполняются самим shell, без нового процесса: `cd`, `pwd`, `echo` (обычно), `umask`, `exit`, `export`.
- `cd` **обязана** быть встроенной: если бы её запускал отдельный процесс, он сменил бы каталог только себе и завершился.
- **Внешние** — отдельные файлы-программы: `/bin/ls`, `/bin/cat`, `/bin/chmod`, `/usr/bin/sort`...
```bash
type cd        # cd is a shell builtin
type ls        # ls is /bin/ls
which grep     # где лежит программа
echo $PATH     # где shell ищет программы, каталоги через «:»
```

### Кавычки и экранирование
| Запись | Что происходит |
|---|---|
| `'текст'` | всё буквально, ничего не подставляется: `'$HOME *'` так и останется |
| `"текст"` | пробелы сохраняются, шаблоны `*` **не** раскрываются, но `$VAR` и `$(cmd)` подставляются |
| `\x` | экранировать один символ: `\*`, `\ ` (пробел), `\$` |
| `` `cmd` `` или `$(cmd)` | подставить вывод команды |

```bash
echo *            # список файлов
echo "*"          # звёздочка
echo '$HOME'      # $HOME
echo "$HOME"      # /home/studs/s561306
echo "Сегодня $(date)"
```
В лабе строки в `echo` взяты в двойные кавычки, чтобы `=` и пробелы попали в файл одной строкой как есть. Без кавычек `echo` всё равно склеил бы слова через **один** пробел, и двойные пробелы потерялись бы.

### Переменные
```bash
x=5            # без пробелов вокруг =
echo $x
echo $HOME $USER $PWD $PATH $SHELL
```

### Объединение команд
| Запись | Смысл |
|---|---|
| `a ; b` | выполнить a, потом b в любом случае |
| `a && b` | b только если a успешна (код 0) |
| `a \|\| b` | b только если a неуспешна |
| `a \| b` | конвейер: вывод a на вход b, работают **одновременно** |
| `a &` | запустить a в фоне |

`mkdir ~/sandbox && cd ~/sandbox` из шапки: перейти, только если каталог удалось создать.

### Скрипт (сценарий)
- Текстовый файл с командами, по одной на строке. Первая строка — **shebang** `#!/bin/sh`: какой интерпретатор его выполняет. Комментарии начинаются с `#`.
- Запуск: `sh lab0.sh` (shebang и право `x` не нужны) или `chmod u+x lab0.sh; ./lab0.sh` (нужны). `./` обязательно, потому что текущего каталога нет в `$PATH`.
- **`sh -x lab0.sh`** — режим трассировки: перед выполнением каждой команды печатается она сама со знаком `+`, уже после подстановки шаблонов. Так ты и снимал скриншоты для отчёта.
- Методичка требует скрипт, чтобы работу можно было **повторить автоматически**.

```bash
nano lab0.sh          # или vi; в nano сохранение — Ctrl+O, выход — Ctrl+X
sh -x lab0.sh         # запуск с трассировкой
```
Удобнее писать скрипт на маке и копировать на helios: `scp -P 2222 lab0.sh s561306@helios.cs.ifmo.ru:~/`. Обрати внимание: у `ssh` порт задаётся `-p`, у `scp` — `-P`.

### Справка
```bash
man ls          # полное руководство (листать пробелом, выход q, поиск /слово)
man 1 chmod     # раздел 1 — команды; man 2 chmod — системный вызов
apropos copy    # найти команды по ключевому слову
ls --help       # на Linux; на FreeBSD обычно нет, используй man
```

## 3. Файловая система и пути

### Одно дерево
- В UNIX **одно дерево** каталогов с корнем `/`. Букв дисков (C:, D:) нет. Другие диски и разделы **монтируются** в какой-то каталог дерева (`mount`, `df -h` покажет, что куда подключено).
- Принцип **«всё есть файл»**: обычные файлы, каталоги, устройства (`/dev/tty` — терминал, `/dev/null`), каналы, сокеты — всё доступно через имена в дереве и работает через одни и те же вызовы `open/read/write`.

### Стандартные каталоги
| Каталог | Что там |
|---|---|
| `/` | корень |
| `/bin`, `/sbin` | основные программы (`ls`, `cat`, `sh`), `sbin` — для администрирования |
| `/usr` | большая часть программ и библиотек (`/usr/bin`, `/usr/lib`, `/usr/local`) |
| `/etc` | конфигурационные файлы (`/etc/passwd`, `/etc/group`) |
| `/home` (на helios `/home/studs/...`) | домашние каталоги пользователей |
| `/tmp` | временные файлы, писать могут все (поэтому ошибки в п. 4 уводили туда) |
| `/var` | изменяемые данные: логи, почта, очереди |
| `/dev` | файлы устройств |
| `/proc` | (в Linux) информация о процессах в виде файлов; на слайде `pid-5` |

### Пути
- Твоя домашняя папка `~` — это `/home/studs/s561306` (на слайде лекции встречается `/export/home/studs/...`, на helios домашние каталоги могут быть смонтированы туда).
- **Абсолютный путь** начинается с `/` и не зависит от того, где ты находишься: `/home/studs/s561306/lab0/bagon`.
- **Относительный путь** считается от **текущего каталога** процесса: `lab0/bagon`, `../bagon`.
- `.` — текущий каталог, `..` — родительский. Это **настоящие записи** в каждом каталоге (жёсткие ссылки), поэтому они видны в `ls -a`. У корня `..` указывает на сам корень.
- `~` — домашний каталог (раскрывает shell), `~user` — домашний каталог другого пользователя.
- Пример со слайда: из `/home/serge/lab0` ссылка `Pikach2 → ../../serge/pikachu` — относительный путь: подняться на 2 уровня (в `/home`), затем `serge/pikachu`.

### Как ядро идёт по пути
Чтобы открыть `/home/studs/s561306/lab0/scizor/wynaut`, ядро проходит каждый каталог по очереди: `/`, `home`, `studs`, ..., `scizor`. **На каждый каталог пути нужно право `x`.** Если хоть у одного нет `x` — `Permission denied`, даже если у самого файла права `777`.

### Имена файлов
- Регистр важен: `Bagon` и `bagon` — разные файлы.
- Можно почти любые символы, кроме `/` и нулевого байта. Пробелы допустимы, но их придётся экранировать.
- **Скрытые файлы** начинаются с точки (`.bashrc`, `.profile`). `ls` их не показывает без `-a`, и шаблон `*` их не захватывает.
- Расширений в понимании ОС нет: `.txt` — просто часть имени.

✏️ **Упр. 1.** В песочнице создай `a/b/c` одной командой, перейди в `c`, выведи `pwd`, вернись в песочницу через `cd ../../..`. Затем то же самое абсолютным путём.

## 4. Типы файлов, inode, каталоги

### Типы файлов (первый символ в `ls -l`)
| Символ | Тип | Пример |
|---|---|---|
| `-` | обычный файл (regular) | `bagon`, `/bin/ls` |
| `d` | каталог (directory) | `chinchou` |
| `l` | символическая ссылка (link) | `Copy_66 -> pansear` |
| `c` | символьное устройство (character): данные идут потоком байтов | `/dev/tty`, `/dev/null` |
| `b` | блочное устройство (block): обмен блоками, произвольный доступ | диски `/dev/ada0` |
| `p` | именованный канал, FIFO (pipe) | создаётся `mkfifo` |
| `s` | сокет (socket) | `/var/run/...` |

Жёсткая ссылка **не** отдельный тип: это обычное имя обычного файла.

```bash
ls -l /dev/null /dev/tty     # c
ls -ld /tmp                  # d
file bagon                   # что внутри файла (текст, программа...)
```

### inode
**inode** (индексный дескриптор) — служебная запись о файле в файловой системе. В ней хранится:
- тип файла и права доступа;
- владелец (UID) и группа (GID);
- размер;
- **счётчик жёстких ссылок**;
- три времени: **atime**, **mtime**, **ctime**;
- где на диске лежат данные (номера блоков).

**Имени в inode нет!** У каждого inode есть номер, уникальный в пределах одной файловой системы: `ls -i` его покажет.

### Каталог
- Каталог — это **файл особого типа**, содержимое которого — таблица записей «**имя → номер inode**».
- Поэтому:
  - **создать, удалить, переименовать** файл = **изменить каталог** (добавить, убрать, поменять запись). Нужно право `w` на каталог, а права самого файла не важны;
  - **прочитать список** имён = **прочитать каталог**, нужно `r`;
  - **найти** файл по имени и попасть в его inode = **поиск в каталоге**, нужно `x`.
- `mv` внутри одной файловой системы не копирует данные, а только переписывает записи в каталогах. Поэтому переименование мгновенное даже для огромного файла.

### Счётчик ссылок у каталога
У каталога в `ls -l` число ссылок = **2 + число подкаталогов**: одна ссылка — его имя в родителе, одна — запись `.` в нём самом, и по одной — запись `..` в каждом подкаталоге. На слайде лекции у `lab0` стоит 5, значит у него 3 подкаталога. Хороший вопрос на защите, проверь на своём дереве: у `scizor` 3 подкаталога (unfezant, furret, jellicent), значит 5.

### Три времени файла
| Время | Что значит | Когда меняется | ключ `ls` |
|---|---|---|---|
| **mtime** (modification) | изменение **содержимого** | запись в файл (`>>`, редактор) | по умолчанию |
| **atime** (access) | последний **доступ** (чтение) | `cat`, запуск | `-u` |
| **ctime** (change) | изменение **inode** («записи о файле») | `chmod`, `ln`, переименование, смена владельца, а также любое изменение содержимого | `-c` |

⚠️ **ctime — это НЕ время создания!** Классическая ловушка. В классическом UNIX время создания не хранилось вообще (в FreeBSD оно есть отдельно, см. 17.7). В задании 4.2 «дата изменения записи о файле» — это именно ctime, поэтому `ls -lRtc`.

## 5. Стандартные потоки ввода-вывода

### Что это
Каждый процесс при запуске получает три открытых **файловых дескриптора** (маленькие числа, которыми процесс ссылается на открытые файлы):

| № | Имя | Назначение | Куда по умолчанию |
|---|---|---|---|
| 0 | **stdin** — стандартный ввод | откуда программа читает данные | клавиатура (терминал `/dev/tty`) |
| 1 | **stdout** — стандартный вывод | куда пишет результат | экран (терминал) |
| 2 | **stderr** — стандартный поток ошибок | куда пишет диагностику и ошибки | экран (терминал) |

**Зачем stderr отдельно:** чтобы ошибки не смешивались с данными. Если перенаправить результат в файл или в конвейер, сообщения об ошибках всё равно останутся на экране, и пользователь их увидит, а файл не испортится. Слайд лекции: `ls -R` пишет список в OUT, а `Permission denied` — в ERR.

**Зачем вообще потоки:** программа не знает и не должна знать, откуда её ввод и куда её вывод. Она просто читает 0 и пишет в 1 и 2, а shell до запуска решает, что за этими номерами стоит: терминал, файл, другой процесс. Это позволяет собирать сложные действия из простых программ.

### Управление потоками в shell (перенаправления)
| Запись | Смысл |
|---|---|
| `cmd > f` | stdout в файл; файл создаётся, а если есть — **обрезается до нуля** (перезапись) |
| `cmd >> f` | stdout **дописать** в конец файла (создать, если нет) |
| `cmd 2> f` | stderr в файл |
| `cmd 2>> f` | stderr дописать в файл |
| `cmd > f 2>&1` | **и** stdout, **и** stderr в файл |
| `cmd 2>&1` | stderr туда же, куда **сейчас** идёт stdout |
| `cmd 1>&2` или `>&2` | stdout в stderr (так скрипты печатают свои ошибки) |
| `cmd 2>/dev/null` | ошибки выбросить |
| `cmd > /dev/null` | вывод выбросить |
| `cmd < f` | stdin из файла |
| `cmd << EOF` ... `EOF` | **here-document**: stdin — строки, набранные дальше, до строки `EOF` |
| `cmd1 \| cmd2` | **конвейер** (pipe): stdout первой идёт на stdin второй |

`>` — это сокращение для `1>`, `<` — для `0<`.

```bash
echo "первая строка" > f.txt      # создать файл с одной строкой
echo "вторая строка" >> f.txt     # дописать вторую
cat f.txt
ls nope 2> /tmp/err_$USER          # ошибка «нет такого файла» уйдёт в файл
cat /tmp/err_$USER
sort <students >by_name 2>/dev/null   # пример со слайда: вход из файла, выход в файл, ошибки в никуда

cat > g.txt << EOF
строка 1
строка 2
EOF
```

### Порядок перенаправлений важен
Shell обрабатывает перенаправления **слева направо**, и `2>&1` значит «сделай 2 копией того, чем 1 является **прямо сейчас**».
- `cmd > f 2>&1` — сначала 1 → f, потом 2 → туда же (f). Оба в файле. ✅
- `cmd 2>&1 > f` — сначала 2 → туда, куда сейчас 1 (экран), потом 1 → f. Ошибки на экране, данные в файле.
- `cmd 2>&1 | grep x` — конвейер настраивается **до** остальных перенаправлений, поэтому 1 уже идёт в трубу, и 2 идёт туда же. Ошибки попадают в grep. ✅ (так в твоих 4.3, 4.4)
- `cmd | grep x 2>&1` — тут `2>&1` относится к **grep**, а ошибки `cmd` по-прежнему идут на экран.

В задании «**добавить вывод ошибок доступа в стандартный поток вывода**» = `2>&1`. «**Ошибки доступа перенаправить в файл в /tmp**» = `2>/tmp/имя`.

### Ловушки
- `sort f > f` — **уничтожит** файл: shell обрежет `f` до нуля **до** запуска sort, и sort прочитает пустой файл.
- `/dev/null` — специальный файл-«чёрная дыра»: всё записанное исчезает, чтение сразу даёт конец файла.
- `tee f` — фильтр, который пишет вход и в stdout, и в файл: `ls | tee list.txt | wc -l`.

### Конвейер подробнее
- Все команды конвейера запускаются **одновременно** как отдельные процессы, а между ними ядро создаёт **канал** (pipe) — буфер в памяти. Первая пишет, вторая читает по мере поступления.
- Код возврата конвейера — код **последней** команды.
- В конвейер попадает только **stdout**. stderr идёт мимо, на экран, если не сказать `2>&1`.

Слайд «Фильтры»: `cat m* 2>/dev/null | grep -v "^V" | sort` — вывести все файлы, начинающиеся на m, ошибки выбросить, убрать строки, начинающиеся на V, отсортировать.

## 6. Фильтры

### Определение
**Фильтр** — программа, которая **читает данные со стандартного ввода** (если ей не дали имён файлов), как-то их преобразует и **пишет результат в стандартный вывод**. Поэтому её можно поставить в середину конвейера: `a | ФИЛЬТР | b`.

| Фильтры | Не фильтры (не читают stdin, работают с аргументами) |
|---|---|
| `cat`, `grep`, `sort`, `head`, `tail`, `wc`, `tee`, `more` (интерактивный, обычно ставят в конец) | `ls`, `echo`, `mkdir`, `touch`, `cp`, `mv`, `rm`, `rmdir`, `ln`, `chmod`, `cd`, `pwd` |

Обрати внимание: `echo` и `ls` **пишут** в stdout (их можно ставить в начало конвейера), но **не читают** stdin, поэтому не фильтры. `echo привет | ls` — `ls` проигнорирует вход.

Если фильтру дали имена файлов, он читает их, а не stdin. Имя `-` обычно означает «stdin»: `echo X | cat a - b`.

### `grep` — поиск строк по шаблону
`grep [ключи] шаблон [файл...]` — выводит строки, в которых есть совпадение с **регулярным выражением**.

| Ключ | Смысл |
|---|---|
| `-v` | инверсия: строки **без** совпадения |
| `-i` | без учёта регистра |
| `-n` | показать номера строк |
| `-c` | только количество подходящих строк |
| `-l` | только имена файлов, где есть совпадение |
| `-w` | совпадение целым словом |
| `-x` | вся строка целиком |
| `-r` | рекурсивно по каталогам |
| `-E` | расширенные регулярные выражения (как `egrep`) |
| `-F` | шаблон — просто строка, без спецсимволов (как `fgrep`) |

Шаблон лучше брать в кавычки, чтобы shell не принял `*` или `$` за свои.

### `sort` — сортировка строк
`sort [ключи] [файл...]`. По умолчанию — посимвольно (лексикографически) по всей строке, по возрастанию.

| Ключ | Смысл |
|---|---|
| `-r` | обратный порядок (по убыванию, z→a) |
| `-n` | сравнивать как **числа** (иначе `10` < `9`, потому что `1` < `9`) |
| `-k N` | ключ сортировки начинается с N-го поля; `-k5` — по 5-му столбцу (размер в `ls -l`); `-k5,5` — только 5-й |
| `-t ':'` | разделитель полей (по умолчанию пробелы) |
| `-u` | убрать повторяющиеся строки |
| `-f` | не различать регистр |
| `-o f` | записать результат в файл (можно в тот же: `sort -o f f`, это безопасно) |

⚠️ Порядок сортировки зависит от **локали** (`LANG`, `LC_COLLATE`): в UTF-8 большие и маленькие буквы могут идти вперемешку, а в `C` сначала все заглавные.

### `head` и `tail`
| Команда | Смысл |
|---|---|
| `head -n 3 f` | первые 3 строки (по умолчанию 10); старая запись `head -3` |
| `tail -n 2 f` | последние 2 строки |
| `tail -n +3 f` | начиная с 3-й строки до конца (на BSD можно `tail +3`) |
| `tail -c 10` | последние 10 байт |
| `tail -f log` | следить за файлом, выводить новые строки по мере дописывания |

«Вывести N последних элементов списка» = `... | tail -n N`. «Первых» = `head -n N`.

### `wc` — подсчёт
`wc [ключи] [файл...]`. Без ключей выводит три числа: **строки, слова, байты**, и имя файла. Если файлов несколько, в конце добавляется строка `total`.

| Ключ | Что считает |
|---|---|
| `-l` | строки (точнее, символы перевода строки) |
| `-w` | слова (последовательности без пробелов) |
| `-c` | **байты** |
| `-m` | **символы** |

В UTF-8 русская буква занимает **2 байта**, но это **1 символ**. Поэтому в 4.1 «количество символов» — это `wc -m`, а не `-c`. Если локаль не UTF-8, `-m` будет считать как `-c`: проверь `locale`.

### `cat`
`cat [-n] [файл...]` — **con**cat**enate**: читает файлы по очереди и выводит подряд. Без файлов читает stdin.
- `-n` — нумеровать все строки (сквозная нумерация через все файлы);
- `-b` — нумеровать только непустые;
- `cat a b > c` — **склеить** файлы в новый (так сделан `zoroark_57`);
- `cat > f` — набрать файл с клавиатуры, конец ввода `Ctrl+D`.

### `more` (и `less`)
Постраничный просмотр: пробел — следующая страница, Enter — строка, `/слово` — поиск, `q` — выход. Если вывод идёт не в терминал, ведёт себя как `cat`. `less` — улучшенный `more` (можно листать назад).

## 7. Регулярные выражения (для grep)

**Регулярное выражение** — шаблон для поиска **внутри строк текста**. Не путать с шаблонами имён файлов (glob, раздел 11): у них похожие символы, но другой смысл, и раскрывает их не shell, а сама программа (grep).

### Базовые (BRE, по умолчанию в grep) — со слайда лекции
| Символ | Значит |
|---|---|
| обычный символ | соответствует сам себе: `grep mkdir` |
| `^` | начало строки: `"^V"` — строки, начинающиеся на V |
| `$` | конец строки: `"n$"` — строки, кончающиеся на n |
| `.` | **один любой** символ: `"т..$"` — «т» и ещё ровно два символа в конце строки |
| `*` | **0 или больше** повторений предыдущего: `"ab*c"` — ac, abc, abbc |
| `[abc]` | один из перечисленных символов |
| `[a-z]` | один из диапазона |
| `[^abc]` | любой, кроме перечисленных |
| `\.` | экранирование: буквальная точка |

### Расширенные (ERE, `grep -E`)
| Символ | Значит |
|---|---|
| `+` | 1 или больше |
| `?` | 0 или 1 |
| `a\|b` | a или b |
| `( )` | группировка |
| `{n,m}` | от n до m повторений |

```bash
grep "^V" messages          # строки, начинающиеся на V
grep -v "^V" messages       # кроме них
grep "т..$" messages        # кончаются на т + 2 любых символа
grep -c "" f                # число строк
grep -E "cat|dog" f         # cat или dog
ls -l | grep "^d"           # только каталоги
ls -l | grep "^l"           # только символические ссылки
```

⚠️ `*` в glob значит «любая строка», а в регулярке — «повтор предыдущего символа». Аналог glob-`*` в регулярке — `.*`.

### Как это было в лабе
- 4.2: `grep "pi"` — строки, где есть подстрока `pi` где угодно (в имени файла, но и в заголовках каталогов вида `./pansear/pidgeotto:`).
- 4.4: `grep -i "ce"` — без учёта регистра. Вывод пуст, потому что «С» в «Способности» — **кириллическая**, а шаблон латинский. Для компьютера это разные символы с разными кодами.
- 4.5: `grep "n$"` — строки `ls -lR`, которые **кончаются** на n, то есть имена на n. Ловушка: у символической ссылки строка кончается на цель (`raltsbagon -> ../bagon`), и попадает она туда по цели, а не по имени.

## 8. `ls` и вывод `ls -l`

### Ключи `ls`
| Ключ | Смысл |
|---|---|
| `-l` | длинный формат (права, ссылки, владелец, размер, дата) |
| `-a` | показать всё, включая скрытые и `.`, `..` |
| `-A` | скрытые, но без `.` и `..` |
| `-R` | рекурсивно: содержимое всех подкаталогов, каждый с заголовком `путь:` |
| `-d` | показать сам каталог, а не его содержимое: `ls -ld chinchou` |
| `-i` | номер inode |
| `-t` | сортировать по времени, **новые сверху** (по убыванию) |
| `-c` | брать **ctime** (для `-l` и для `-t`) |
| `-u` | брать **atime** |
| `-S` | сортировать по размеру, **большие сверху** (по убыванию) |
| `-r` | обратить порядок сортировки |
| `-F` | дописать значок типа: `/` каталог, `@` ссылка, `*` исполняемый |
| `-n` | числовые UID/GID |
| `-h` | размеры в K, M, G |
| `-1` | по одному имени в строке |

По умолчанию `ls` сортирует по имени. Комбинации из лабы: `-lRtc` (рекурсивно, по ctime, новые сверху), `-lSr` (по размеру по возрастанию).

⚠️ `ls -r` — обратный порядок, `ls -R` — рекурсия. У `cp`, `rm`, `chmod` наоборот: рекурсия задаётся `-r`/`-R`.

### Разбор строки `ls -l`
```
-rw-r--r--  1 s561306 studs  183 Sep 28 12:00 zoroark
│└┬┘└┬┘└┬┘  │    │       │     │       │         └ имя
│ │  │  │   │    │       │     │       └ дата и время (по умолчанию mtime)
│ │  │  │   │    │       │     └ размер в байтах
│ │  │  │   │    │       └ группа-владелец
│ │  │  │   │    └ владелец
│ │  │  │   └ число жёстких ссылок
│ │  │  └ права остальных (o)
│ │  └ права группы (g)
│ └ права владельца (u)
└ тип: - файл, d каталог, l символическая ссылка, c b p s
```
- Первая строка `total N` — сколько **блоков** диска занимают перечисленные файлы (не байт и не файлов!).
- У **символической ссылки** в конце `имя -> цель`, права всегда `lrwxrwxrwx`, а размер = **длина строки пути** цели. На слайде `Copy_50 -> Xatu9/` размер 5 = длина «Xatu9».
- У **каталога** размер — размер служебной таблицы записей, к содержимому отношения не имеет. На helios (ZFS) там примерно число записей в каталоге.
- Если файл старше полугода, вместо времени показывается год.
- Если прав не хватает, `ls -lR` напишет об ошибке в **stderr** и пойдёт дальше. В русской локали helios это «Недостаточно привилегий» / «Permission denied».

### Пример со слайда
```
dr-x--x-wx 5 s207549 studs 9 дек. 8 2015 Flareon0/
```
Каталог, владелец `r-x` (смотреть и заходить, но не создавать), группа `--x` (только заходить по известному имени), остальные `-wx` (создавать и удалять файлы вслепую, не видя список). 5 ссылок → 3 подкаталога.

## 9. Права доступа

### Кто и что
Три категории: **u** — владелец (user), **g** — группа-владелец (group), **o** — остальные (others). **a** (all) = ugo.
Три права: **r** (read), **w** (write), **x** (execute).

| | Для файла | Для каталога |
|---|---|---|
| **r** | читать содержимое (`cat`, `cp` из него) | **видеть список** имён (`ls`, раскрытие шаблонов `*`, `cp -r`, `rm -r`) |
| **w** | изменять содержимое (`>`, `>>`, редактор) | **создавать, удалять, переименовывать** записи внутри (нужен ещё x) |
| **x** | запускать как программу | **заходить** (`cd`), обращаться к файлам внутри **по имени**, проходить насквозь в путях |

⚠️ Главная ловушка лабы: удалить или создать файл — это изменить **каталог**, в котором он лежит. Права самого файла тут вторичны.

### Комбинации для каталога (часто спрашивают)
| Права | Что можно |
|---|---|
| `r--` | увидеть имена (`ls` покажет их, но с ошибками: ни размеров, ни прав не узнать), зайти нельзя, открыть файл нельзя |
| `--x` | зайти, открыть файл, **если знаешь его имя**; `ls` не работает, `*` не раскрывается |
| `r-x` | читать: смотреть список, заходить, открывать файлы. Создавать и удалять нельзя (это `pansear` = 551) |
| `-wx` | создавать и удалять файлы, если знаешь имена, но не видеть список (это твой `chinchou` у владельца = 3) |
| `rwx` | всё |
| `-w-` | бесполезно: без x ни создать, ни удалить |

### Что нужно для типовых действий
| Действие | Права |
|---|---|
| прочитать файл `d/f` | `x` на `d` + `r` на `f` |
| изменить файл `d/f` | `x` на `d` + `w` на `f` |
| создать файл в `d` | `w` + `x` на `d` |
| **удалить** файл из `d` | `w` + `x` на `d`, права на сам файл **не нужны** |
| переименовать `d/a` → `d/b` | `w` + `x` на `d` |
| `ls d` | `r` на `d` (для `ls -l` ещё и `x`) |
| `cd d` | `x` на `d` |
| `cp f d/` | `r` на `f`, `w`+`x` на `d` |
| `cp -r src dst` | `r`+`x` на все каталоги внутри `src`, `r` на все файлы |
| `rm -r d` | `r`+`w`+`x` на `d` и на все подкаталоги |
| `chmod` | быть **владельцем** файла (или root), права на сам файл не нужны |
| `ln f d/h` (жёсткая) | `w`+`x` на `d`; права на `f` не нужны (в лабе `ln bagon` сработал при правах 004) |
| `ln -s цель d/s` | `w`+`x` на `d`; цель может даже не существовать |

Про `rm` и защищённый от записи файл: если у файла нет `w`, а ты в терминале, `rm` **спросит** «override r--------?». Это просто вежливость команды, ядро удалить позволит. Ключ `-f` убирает вопрос. Поэтому в твоём п. 5 `rm -f bagon` (у bagon права 004).

### Два способа задать права в `chmod`
**Числовой (восьмеричный, абсолютный):** r = 4, w = 2, x = 1, складываем внутри каждой тройки. Получаются 3 восьмеричные цифры: u, g, o. Задаёт права **целиком**, старые забываются.
```
rw- r-- r--  →  110 100 100  →  6 4 4  →  chmod 644 f
rwx r-x --x  →  111 101 001  →  7 5 1  →  chmod 751 d
rw- r-- ---  →  110 100 000  →  6 4 0  →  chmod 640 f
```
Каждая тройка — это 3 бита, поэтому одна восьмеричная цифра (0–7) ровно описывает одну тройку. Именно поэтому система **восьмеричная**.

| Цифра | Права |
|---|---|
| 0 | `---` |
| 1 | `--x` |
| 2 | `-w-` |
| 3 | `-wx` |
| 4 | `r--` |
| 5 | `r-x` |
| 6 | `rw-` |
| 7 | `rwx` |

**Символьный (относительный или точный):** `[кому][оператор][что]`, несколько через запятую без пробелов.
- кому: `u`, `g`, `o`, `a` (если не указано — как `a`, но с учётом umask);
- оператор: `+` добавить, `-` убрать, `=` установить ровно (остальное в этой тройке убрать);
- что: `r`, `w`, `x` (и `X`, `s`, `t` — см. ниже).
```bash
chmod u+x f          # владельцу добавить x, остальное не трогать
chmod go-w f         # группе и остальным убрать w
chmod u=rw,g=r,o= f  # точно задать все три тройки (o= — ничего)
chmod a=r f          # всем только чтение
chmod ug=rw,o=r f    # как у твоего zoroark → 664
chmod u+w,o-r f      # можно смешивать + и -
```
Со слайда лекции: от `rw-r--r--` (644) командой `u+x g+rx o=x` получаем `rwxr-x--x` (751); `a-x` от 751 даёт `rw-r-----` (640).

**Когда что удобно:** числовой — когда надо задать права целиком и известен итог. Символьный — когда надо **поменять одно право**, не трогая остальные (как `chmod u+w pansear` в п. 3 и 5), и когда права заданы словами.

`chmod -R` — рекурсивно для каталога и всего внутри.

В лабе нужно использовать **оба способа** («различные способы указания прав»), поэтому в скрипте они чередуются.

### umask — права по умолчанию
- Когда программа создаёт файл, она просит права (обычно `666` для файлов и `777` для каталогов), а ядро **убирает** из них биты, заданные в **umask** процесса.
- Типичный umask `022`: файлы получаются `644` (`rw-r--r--`), каталоги `755` (`rwxr-xr-x`). При umask `077` — `600` и `700`.
- Это не вычитание, а «выключение битов»: `666` с umask `033` даст `644`, а не `633`.
- Поэтому файлы, созданные `echo >` в п. 1, сразу получили не `777`, а `644`, а каталоги из `mkdir` — `755` (если на helios umask 022; проверь командой `umask`).
- `x` для новых файлов не ставится никогда — его добавляют руками.

### Специальные биты (на защите иногда спрашивают «а что такое 4-я цифра»)
Права на самом деле 12-битные: перед тремя тройками есть ещё 3 бита, это четвёртая (самая левая) восьмеричная цифра.

| Бит | Число | На файле | На каталоге | В `ls -l` |
|---|---|---|---|---|
| **SUID** (set user ID) | 4000 | программа выполняется с правами **владельца** файла, а не запустившего | — | `s` вместо `x` у u |
| **SGID** (set group ID) | 2000 | выполняется с правами группы файла | новые файлы наследуют группу каталога | `s` вместо `x` у g |
| **sticky** | 1000 | — | удалять файл может только его владелец (и владелец каталога) | `t` вместо `x` у o |

Примеры: `/usr/bin/passwd` имеет SUID root, чтобы обычный пользователь мог поменять свой пароль в системном файле. `/tmp` имеет права `1777` (`drwxrwxrwt`): писать могут все, но удалить чужой файл нельзя.

Если в `ls -l` видна **заглавная** `S` или `T`, бит стоит, а `x` под ним нет.

✏️ **Упр. 5б.** Переведи в буквы: `355`, `771`, `305`, `711`. Затем запиши каждый символьной командой `chmod`.

## 10. Ссылки

### Жёсткая ссылка (`ln цель имя`)
- Это **ещё одна запись в каталоге**, которая указывает на **тот же самый inode**. Новый файл не создаётся.
- Все имена **равноправны**: нельзя сказать, какое «настоящее», а какое «ссылка».
- Счётчик ссылок в inode (2-й столбец `ls -l`) увеличивается на 1.
- `rm` на самом деле не удаляет файл, а удаляет **имя** (вызов `unlink`) и уменьшает счётчик. Данные освобождаются, только когда счётчик стал **0** и файл никем не открыт.
- Права, владелец, размер, время, содержимое у всех имён **общие**, потому что хранятся в одном inode. Изменишь через одно имя — изменится и через другое.
- **Ограничения:** работает только **в пределах одной файловой системы** (номер inode уникален только внутри неё); нельзя делать на **каталоги** (иначе в дереве могли бы появиться циклы), кроме служебных `.` и `..`, которые создаёт сама система.

### Символическая (мягкая) ссылка (`ln -s цель имя`)
- Это **отдельный файл** со своим inode, типа `l`, внутри которого записан **путь** к цели (как ярлык).
- Когда программа открывает ссылку, ядро подставляет записанный путь и идёт дальше по нему.
- Может указывать **на каталог** (твой `Copy_66 -> pansear`), **на другую файловую систему**, даже **на несуществующий** путь.
- Если цель удалить или переименовать, ссылка **«висит»** (dangling, битая): `cat` выдаст «No such file or directory». Счётчик ссылок цели символическая ссылка **не увеличивает**.
- Её права `lrwxrwxrwx` ни на что не влияют: проверяются права **цели**.
- Размер = длина записанного пути.
- **Относительный путь внутри ссылки считается от каталога, где лежит сама ссылка**, а не от текущего каталога в момент создания.

```bash
cd ~/lab0
ln -s ../bagon pansear/raltsbagon   # ссылка лежит в pansear, поэтому до bagon — «../bagon»  ✅
ln -s bagon pansear/raltsbagon      # НЕВЕРНО: ссылка будет искать pansear/bagon
ln -s pansear Copy_66               # ссылка лежит в lab0, цель тоже в lab0  ✅
```

### Сравнение (готовая таблица для ответа)
| | Жёсткая | Символическая |
|---|---|---|
| Что создаётся | новое имя для того же inode | новый файл со своим inode, внутри путь |
| Тип в `ls -l` | как у цели (`-`) | `l` |
| На каталог | нельзя | можно |
| Между файловыми системами | нельзя | можно |
| Если удалить исходное имя | данные доступны по ссылке | ссылка висит |
| Счётчик ссылок цели | +1 | не меняется |
| Права | общие с целью | свои `rwxrwxrwx`, не используются |
| Номер inode (`ls -i`) | такой же | другой |

### Что было в лабе
- `ln bagon pansear/cranidosbagon` — после этого у `bagon` и `cranidosbagon` в `ls -l` одинаковые права (`------r--`), размер и счётчик **2**.
- В п. 5 после `rm -f bagon` счётчик стал 1, данные остались доступны через `cranidosbagon`, а символическая `raltsbagon` повисла.
- `rm Copy_*` удалил **саму ссылку** `Copy_66`, каталог `pansear` не пострадал. Опасность: `rm -r Copy_66/` (со слэшем) пошёл бы **внутрь** каталога по ссылке.

## 11. Шаблоны имён (glob)

| Шаблон | Значит |
|---|---|
| `*` | любая строка, в том числе пустая |
| `?` | ровно один любой символ |
| `[abc]` | один из перечисленных |
| `[a-z]` | один из диапазона |
| `[!abc]` | любой, кроме перечисленных |

Шаблоны раскрывает **shell** до запуска команды, подставляя список подходящих имён по алфавиту:
```bash
ls *t          # всё в текущей папке, что заканчивается на t
cat */*t       # файлы на t на один уровень глубже
cat */*/*t     # на два уровня глубже
rm Copy_*      # всё, что начинается с Copy_
echo *         # посмотреть, во что раскроется шаблон
```
- `*` **не захватывает** скрытые файлы (начинающиеся с `.`) и **не проходит** через `/`: `*t` не найдёт `scizor/wynaut`, для этого нужен `*/*t`.
- ⚠️ Если у папки нет права **r**, shell не может прочитать список её файлов, и шаблон `папка/*` **не раскроется**. В sh и bash команда получит буквальную строку `папка/*` и напишет «No such file or directory». Так получилось в 4.1 с `chinchou/*`.
- Если ничего не подошло, sh/bash тоже передают шаблон как есть (а csh и zsh выдают ошибку «No match»).
- Glob ≠ регулярные выражения: в glob `*` — любая строка, в регулярке `*` — повтор предыдущего символа.

## 12. Карточки команд из лабы (для вопроса «Расскажите про команду …»)

Схема ответа: **что делает → синтаксис и ключи → сколько и каких аргументов → фильтр или нет → пример из лабы**.

Синтаксис со слайда лекции:
```
mkdir [-m mode] [-p] dir...        cp [options] SOURCE ... DEST
echo [string]...                   rm [options] [file/dir]
cat [-n] [file...] [-]             rmdir [dir]
touch [-am]... file...             mv [-fi] SOURCE ... DEST
ls [options] [file/dir]...         head [-num] [file...]
pwd                                tail [-/+num] [-bcl] [file...]
cd [argument]                      sort [-unr] [-k num] [file...]
more [file...]                     grep [-v] regexp [file...]
                                   wc [-c | -m ] [-lw] [file...]
```
`[...]` — необязательно, `...` — можно повторить, `|` — одно из двух.

**`mkdir`** — создать каталог(и). Аргументы: 1 и больше имён. `-p` — создать все недостающие родительские и не ругаться, если каталог уже есть. `-m 755` — сразу задать права. Новый каталог сразу содержит `.` и `..`, счётчик ссылок 2, у родителя счётчик +1. Ошибки: каталог уже есть; нет родителя (без `-p`); нет `w`+`x` на родителя. Не фильтр. В лабе: `mkdir chinchou chinchou/duskull ...` — сначала родитель, потом дети, в одной команде можно, потому что аргументы обрабатываются по порядку.

**`echo`** — напечатать аргументы через пробел в stdout и перевод строки. 0 и больше аргументов. `-n` — без перевода строки (в sh может не работать, переносимее `printf`). Встроена в shell (есть и `/bin/echo`). Не фильтр, stdin не читает. В лабе: создание файлов, `>` — первая строка, `>>` — следующие.

**`cat`** — склеить файлы и вывести в stdout. 0 и больше файлов, `-` — stdin. `-n` — номера строк, `-b` — номера только непустых. **Фильтр.** В лабе: `cat pansear/metagross pansear/metagross > zoroark_57` (один файл дважды), `cat bagon > scizor/wynautbagon` (копия через перенаправление), `cat -n` в 4.3 и 4.4.

**`touch`** — обновить время доступа и изменения файла на текущее; если файла нет — создать **пустой**. 1 и больше файлов. `-a` — только atime, `-m` — только mtime, `-t` — задать время. Не фильтр.

**`ls`** — список содержимого каталогов или информация о файлах. 0 и больше аргументов (по умолчанию `.`). Ключи — раздел 8. Не фильтр (не читает stdin), но часто начинает конвейер. В лабе: 4.2, 4.5, 4.6, `ls -lR` для отчёта.

**`pwd`** — print working directory, абсолютный путь текущего каталога. Без аргументов. Встроена в shell. Не фильтр.

**`cd`** — сменить текущий каталог shell. 0 или 1 аргумент: без аргумента — в домашний, `cd -` — в предыдущий, `cd ..` — вверх. Встроена, потому что меняет состояние самого shell. Нужно право `x` на каталог. Не фильтр.

**`more`** — постраничный просмотр файлов или stdin. Технически фильтр (читает stdin), но интерактивный, поэтому ставится в конце конвейера: `ls -lR | more`.

**`cp`** — копировать. Формы: `cp src dst` (файл в файл), `cp src... каталог/` (несколько файлов в каталог). 2 и больше аргументов, последний — куда. `-r`/`-R` — каталоги рекурсивно, `-i` — спрашивать перед перезаписью, `-f` — перезаписывать без вопросов, `-p` — сохранить права, владельца и время. Без `-p` копия получает права исходника, из которых umask убирает свои биты (при umask 022 копия `zoroark` с правами 664 станет 644; проверь `ls -l scizor/furret`), владельцем становится тот, кто копирует, время — текущее. Если целевой каталог **существует**, копия ляжет **внутрь** него: `cp -r chinchou pansear/pidgeotto` создало `pansear/pidgeotto/chinchou`. Новый inode, данные дублируются. Не фильтр.

**`mv`** — переместить или переименовать. 2 и больше аргументов. `-i` — спросить, `-f` — не спрашивать. Внутри одной файловой системы только меняет записи в каталогах (inode тот же, данные не копируются), между ФС — копирует и удаляет. Нужно `w`+`x` на оба каталога. Не фильтр.

**`rm`** — удалить имена файлов (`unlink`). 1 и больше аргументов. `-r`/`-R` — каталог со всем содержимым, `-f` — не спрашивать и не ругаться на отсутствие файла, `-i` — спрашивать про каждый. Без `-r` каталоги не удаляет. Удаляет ссылку, а не цель. Восстановить нельзя, корзины нет. Нужно `w`+`x` на каталог, где лежит имя. Не фильтр. В лабе: весь п. 5.

**`rmdir`** — удалить **пустые** каталоги. 1 и больше аргументов. `-p` — удалить и пустых родителей. Если внутри что-то есть (кроме `.` и `..`) — ошибка «Directory not empty». Нужно `w`+`x` на родителя. Не фильтр. В лабе: `rmdir chinchou/starmie` сработал, хотя у `chinchou` для владельца нет `r` (права `-wx`): чтобы удалить запись по имени, `r` не нужен.

**`ln`** — создать ссылку. `ln цель имя` — жёсткую, `ln -s цель имя` — символическую. 2 аргумента (или несколько целей и каталог). `-f` — заменить существующее имя. Не фильтр. В лабе: `Copy_66`, `raltsbagon`, `cranidosbagon`.

**`chmod`** — изменить права. `chmod права файл...`, 2 и больше аргументов; права числом или символами (раздел 9). `-R` — рекурсивно. Менять может только владелец или root. Меняет ctime. Не фильтр. Есть родственные `chown` (сменить владельца, только root) и `chgrp` (сменить группу).

**`head`** — первые строки (по умолчанию 10). `-n N` или `-N`, `-c N` — байты. 0 и больше файлов. **Фильтр.**

**`tail`** — последние строки (по умолчанию 10). `-n N`, `-n +N` (с N-й строки), `-c`, `-f`. 0 и больше файлов. **Фильтр.** В лабе: 4.2, 4.5.

**`sort`** — сортировка строк (раздел 6). 0 и больше файлов. **Фильтр.** В лабе: 4.1, 4.3, 4.5.

**`grep`** — строки по регулярному выражению (разделы 6 и 7). 1 шаблон + 0 и больше файлов. **Фильтр.** В лабе: 4.2, 4.4, 4.5.

**`wc`** — подсчёт строк, слов, байтов, символов. 0 и больше файлов. **Фильтр.** В лабе: 4.1.

Ещё полезные (не в лабе, но могут спросить для общего развития): `find` (поиск файлов по имени, типу, правам: `find . -name "*t"`), `file` (тип содержимого), `stat` (вся информация из inode), `df` (место на дисках), `du` (размер каталога), `less`, `tee`, `chown`, `chgrp`.

## 13. Ошибки, которые выдаёт shell и команды

| Сообщение | Что значит | Типичная причина в лабе |
|---|---|---|
| `Permission denied` / «Недостаточно привилегий» | ядро отказало в доступе | нет `r` на файл, нет `w`/`x` на каталог |
| `No such file or directory` | имени нет | опечатка, или нераскрывшийся шаблон, или висячая ссылка |
| `File exists` | имя уже занято | повторный `mkdir`, `ln` |
| `Is a directory` | ожидался файл, дали каталог | `cat` на каталог в 4.3 (`*t` поймал каталоги на t) |
| `Not a directory` | ожидался каталог | в пути файл используется как каталог |
| `Directory not empty` | `rmdir` на непустой каталог | |
| `Operation not permitted` | действие запрещено (не про rwx): например, `chmod` чужого файла | |
| `command not found` | программа не найдена в `$PATH` | опечатка |

Все эти сообщения идут в **stderr**, поэтому их можно отдельно перенаправлять.

## 14. helios и удалённая работа
- `ssh` (Secure Shell) — зашифрованное подключение к удалённому серверу, на нём запускается твой shell. Порт helios **2222** (`-p 2222`).
- `scp` — копирование файлов по ssh (`-P 2222`, заглавная). `scp файл s561306@helios.cs.ifmo.ru:~/путь` — на сервер; наоборот — с сервера.
- Выход: `exit` или `Ctrl+D`.
- Полезные клавиши: `Tab` — дополнить имя, `↑` — история, `Ctrl+C` — прервать команду, `Ctrl+D` — конец ввода, `Ctrl+L` — очистить экран.
- `/tmp` на helios общий для всех студентов, поэтому файлы ошибок стоит называть уникально (`/tmp/s561306_err1`), иначе можешь наткнуться на чужой файл без прав на запись.

## 15. Разбор твоего скрипта `lab0.sh`

### П. 1. Дерево
```sh
cd ~ ; mkdir lab0 ; cd lab0
mkdir chinchou chinchou/duskull chinchou/geodude chinchou/starmie
...
echo "Возможности = Overland=6 Surface=4" > bagon
echo "Jump=3 Power=2 Intelligence=3" >> bagon
```
- Каталоги создаются раньше файлов в них. В одной команде `mkdir` родитель указан раньше детей, поэтому всё работает без `-p`.
- `>` создаёт файл (или обнуляет) и пишет первую строку, `>>` дописывает. Каждый `echo` добавляет `\n` в конце, поэтому строки получаются отдельными.
- Права новых файлов и каталогов здесь задаёт umask.
- Почему `echo`, а не `cat > f`: `cat` пришлось бы вводить с клавиатуры, а в скрипте нужно всё автоматически (можно было бы через here-document `cat > f << EOF`).

### П. 2. Права
```sh
chmod 355 chinchou/duskull          # -wxr-xr-x   число
chmod ug=rw,o= chinchou/drapion     # rw-rw----   символы
chmod 771 chinchou/geodude          # rwxrwx--x
chmod u=wx,g=,o=rwx chinchou/starmie   # -wx---rwx = 307
...
chmod 357 chinchou                  # -wxr-xrwx
chmod u=rx,g=rx,o=x pansear         # r-xr-x--x = 551
chmod 700 scizor                    # rwx------
```
- **Почему сначала вложенные, потом родители.** Если сначала отнять у родителя `x` или `r`, то до вложенных уже не добраться (а `chmod` на вложенные требует пройти через родителя). Безопаснее идти снизу вверх.
- Словесные права переведены так: «записывать и переходить» = `wx` = 3, «читать и переходить» = `rx` = 5, «только переходить» = `x` = 1, «не иметь никаких прав» = 0.
- Сообщения «Недостаточно привилегий» в `ls -lR` после п. 2 — нормально: у `chinchou` и `omastar` у владельца нет `r`, поэтому их содержимое не выводится.

### П. 3. Ссылки и копирование (с исправлением ошибок)
```sh
ln -s pansear Copy_66                       # работает: w у lab0 есть
cat pansear/metagross pansear/metagross > zoroark_57   # metagross 666, pansear r-x — читать можно
cp zoroark scizor/furret                    # zoroark rw-, furret rwx — ок; копия ляжет внутрь furret
chmod u+w pansear                           # pansear r-x: создать в нём ссылку без w нельзя
ln -s ../bagon pansear/raltsbagon           # путь ../ — от каталога ссылки
chmod u-w pansear                           # вернуть как было
chmod u+r bagon                             # bagon 004: владельцу читать нельзя
cat bagon > scizor/wynautbagon
chmod u-r bagon
chmod u+w pansear
ln bagon pansear/cranidosbagon              # жёсткая, тоже новая запись в pansear
chmod u-w pansear
chmod u+r chinchou chinchou/duskull chinchou/starmie   # cp -r должен читать списки
cp -r chinchou pansear/pidgeotto            # pidgeotto существует → копия внутри
chmod u-r chinchou chinchou/duskull chinchou/starmie
ls -lR
```
- Логика каждой ошибки: **создание** имени в `pansear` требует `w` на `pansear`; **чтение** `bagon` требует `r` на `bagon`; **копирование каталога** требует `r` на каждый копируемый каталог.
- После каждого исправления права возвращаются, чтобы итоговое дерево соответствовало п. 2. Методичка требует показать в отчёте **и ошибки, и исправляющие команды**.
- Почему `cat bagon > wynautbagon`, а не `cp`: задание говорит «скопировать **содержимое** в новый файл», и пункт явно про `cat` и перенаправление.
- У скопированного `chinchou` внутри `pidgeotto` права берутся от оригинала на момент копирования (с временно добавленным `u+r`) с учётом umask, поэтому могут отличаться от исходных. Проверь `ls -lR pansear/pidgeotto` и будь готов объяснить.

### П. 4. Поиск и фильтрация
```sh
wc -m chinchou/* 2>/tmp/s561306_err1 | sort -n
```
4.1. «Количество символов» → `wc -m`; «по увеличению» → `sort -n`; «ошибки в /tmp» → `2>/tmp/...`. Вывод пуст: у `chinchou` нет `r` у владельца, `*` не раскрылся, `wc` получил буквальное `chinchou/*` и записал ошибку в файл.

```sh
ls -lRtc 2>/tmp/s561306_err2 | grep "pi" | tail -n 2
```
4.2. «Рекурсивный список имён и атрибутов» → `ls -lR`; «по убыванию даты изменения записи о файле» → `-t` (новые сверху = убывание) + `-c` (ctime); «содержащих pi» → `grep "pi"`; «два последних» → `tail -n 2`. Оговорка: при `-R` сортировка идёт **внутри каждого каталога** отдельно, общего списка нет.

```sh
cat -n *t */*t */*/*t 2>&1 | sort -r
```
4.3. «Рекурсивно … имя заканчивается на t» → шаблоны на разные глубины (glob не рекурсивный); «с номерами строк» → `cat -n`; «z→a» → `sort -r`; «добавить ошибки в stdout» → `2>&1` **до** `|`. В вывод попало содержимое `scizor/wynaut` и `Is a directory` для каталогов на t, плюс ошибки доступа.

```sh
cat -n zoroark 2>&1 | grep -i "ce"
```
4.4. «С номерами строк» → `cat -n` (а не `grep -n`: номера должны быть исходного файла, и `cat -n` их проставляет до фильтрации — результат одинаковый, но так соблюдено задание); «регистр игнорировать» → `-i`. Пусто, потому что «С» кириллическая.

```sh
ls -lR 2>/tmp/s561306_err5 | grep "n$" | sort -k5 -nr | tail -n 3
```
4.5. «Заканчивающихся на n» → `grep "n$"`; «по убыванию размера» → 5-й столбец `ls -l` — размер, `-k5 -nr`; «три последних» → `tail -n 3` (то есть три самых маленьких).

```sh
ls -lSr scizor 2>&1
```
4.6. «По возрастанию размера» → `-S` (по убыванию) + `-r` (обратить). Здесь `2>&1` без конвейера ничего видимо не меняет: оба потока и так на экране.

### П. 5. Удаление
```sh
rm -f bagon                    # bagon 004: без -f rm спросил бы про защищённый файл
rm -f scizor/snover            # snover 400 — то же
rm Copy_*                      # удаляется ссылка, а не pansear
chmod u+w pansear
rm pansear/cranidosbag*        # pansear r-x → нужен w
chmod u-w pansear
chmod -R u+rwx pansear         # rm -r должен читать и менять все вложенные каталоги
rm -r pansear
rmdir chinchou/starmie         # starmie пуст; chinchou -wx: w и x хватает
```
- `rm bagon` не удалил данные: они остались доступны через `cranidosbagon`, пока и его не удалили вместе с `pansear`.
- Почему `chmod -R u+rwx pansear` работает, хотя внутри есть каталоги без `r`: `chmod -R` сначала меняет права каталога, а потом заходит в него, так что к моменту чтения `r` уже есть.

## 16. Вопросы, которые могут задать на защите (с короткими ответами)

**Общие**
1. *Что такое ОС?* Комплекс программ, управляющий ресурсами компьютера и дающий интерфейс программам и пользователю. Ядро + драйверы + утилиты.
2. *Что такое ядро?* Часть ОС, работающая в привилегированном режиме: память, процессы, файловые системы, сеть, драйверы. Программы обращаются к нему через системные вызовы.
3. *Что такое shell?* Командный интерпретатор: программа, которая читает команды, раскрывает шаблоны и переменные, настраивает потоки и запускает программы. Примеры: sh, bash, csh, ksh.
4. *Чем отличается программа от процесса?* Программа — файл, процесс — программа в выполнении со своей памятью, PID, правами, открытыми файлами.
5. *Какая ОС на helios?* FreeBSD — ветка BSD.
6. *Что такое POSIX?* Стандарт поведения UNIX-подобных систем.

**Файлы**
7. *Что значит «всё есть файл»?* Устройства, каналы, сокеты представлены именами в дереве и работают через те же вызовы, что обычные файлы.
8. *Какие типы файлов бывают?* `-` обычный, `d` каталог, `l` символическая ссылка, `c` символьное устройство, `b` блочное, `p` FIFO, `s` сокет.
9. *Что такое inode? Где хранится имя?* Служебная запись о файле (тип, права, владелец, размер, времена, счётчик ссылок, блоки). Имя хранится не в inode, а в каталоге.
10. *Что такое каталог?* Файл со списком пар «имя → номер inode».
11. *Почему у каталога счётчик ссылок ≥ 2?* Имя в родителе + `.` внутри; каждый подкаталог добавляет ещё 1 своим `..`.
12. *Абсолютный и относительный путь?* Абсолютный от `/`, относительный от текущего каталога.
13. *Что такое `.` и `..`?* Жёсткие ссылки на текущий и родительский каталог.
14. *Что такое ctime? Это время создания?* Нет. Время последнего изменения inode (права, ссылки, имя, а также содержимое). mtime — содержимого, atime — доступа.

**Ссылки**
15. *Разница жёсткой и символической?* Таблица из раздела 10.
16. *Почему нельзя жёсткую ссылку на каталог?* Могли бы появиться циклы в дереве, и команды вроде `rm -r` и `find` ушли бы в бесконечность; плюс сломался бы однозначный `..`.
17. *Почему нельзя жёсткую ссылку на другую ФС?* Номер inode уникален только внутри одной ФС.
18. *Что будет с жёсткой ссылкой, если удалить исходный файл?* Ничего, данные доступны, счётчик уменьшится.
19. *А с символической?* Повиснет.
20. *Откуда считается относительный путь в символической ссылке?* От каталога, где лежит ссылка.
21. *Какие права у символической ссылки и важны ли они?* `rwxrwxrwx`, не важны, проверяются права цели.
22. *Что удаляет `rm` на самом деле?* Имя (запись в каталоге), уменьшает счётчик; данные исчезают при счётчике 0.

**Права**
23. *Что значат r, w, x для файла и для каталога?* Таблица из раздела 9.
24. *Как удалить файл, на который у тебя нет никаких прав?* Нужны `w` и `x` на каталог, права самого файла не важны.
25. *Почему владелец не может прочитать `bagon` с правами 004, хотя «остальным» можно?* Проверяется только одна категория: для владельца — u, и там `---`.
26. *Что будет, если у каталога есть x, но нет r?* Внутрь заходить и открывать файлы по известному имени можно, а список посмотреть нельзя, шаблоны не раскрываются.
27. *А если r, но нет x?* Видны имена, но нельзя зайти и обратиться ни к одному файлу, `ls -l` не покажет атрибуты.
28. *Два способа задать права в chmod?* Числовой (абсолютный, восьмеричный) и символьный (`u+x`, `go-w`, `a=r`). Когда что удобнее.
29. *Почему права восьмеричные?* Каждая тройка rwx — 3 бита, это ровно одна восьмеричная цифра.
30. *Кто может менять права?* Владелец и root.
31. *Что такое umask?* Маска битов, которые убираются из прав новых файлов. 022 → файлы 644, каталоги 755.
32. *Что такое SUID, SGID, sticky?* Раздел 9, специальные биты; `/tmp` = 1777.
33. *Переведи 751, 640, 357 и обратно* — тренируйся по таблице цифр.

**Потоки**
34. *Какие стандартные потоки, их номера и назначение?* stdin 0, stdout 1, stderr 2.
35. *Зачем stderr отдельно от stdout?* Чтобы ошибки не смешивались с данными при перенаправлении и в конвейерах.
36. *Чем `>` отличается от `>>`?* Перезапись и дописывание.
37. *Что делает `2>&1`?* Направляет stderr туда же, куда сейчас идёт stdout.
38. *Почему важен порядок `> f 2>&1` и `2>&1 > f`?* Перенаправления выполняются слева направо.
39. *Что такое конвейер?* `a | b` — stdout a подаётся на stdin b, процессы работают одновременно, связаны каналом.
40. *Что такое фильтр? Примеры?* Читает stdin, пишет stdout: cat, grep, sort, head, tail, wc.
41. *ls — фильтр? echo?* Нет, они не читают stdin.
42. *Что такое /dev/null?* Устройство, поглощающее всё записанное.
43. *Что такое here-document?* `<< EOF` — ввод из следующих строк скрипта до метки.
44. *Кто выполняет перенаправление — команда или shell?* Shell, до запуска команды.

**Шаблоны и регулярки**
45. *Кто раскрывает `*`?* Shell.
46. *Почему `chinchou/*` не раскрылся?* Нет `r` на `chinchou`, shell не прочитал список.
47. *Чем glob отличается от регулярного выражения?* Glob — для имён файлов, раскрывает shell; регулярка — для строк текста, разбирает программа (grep). `*` в них значит разное.
48. *Что значат `^`, `$`, `.` в регулярке?* Начало строки, конец строки, один любой символ.
49. *Почему 4.4 дала пустой вывод?* Буква «С» в «Способности» кириллическая.

**Про твою лабу**
50. *Почему права ставились сначала на вложенные?* Чтобы не потерять доступ к ним, отняв права у родителя.
51. *Почему понадобились `chmod u+w pansear` и `u+r bagon` в п. 3?* Создание имени требует w на каталог, чтение — r на файл.
52. *Почему `rmdir chinchou/starmie` сработал без `r` на `chinchou`?* Для удаления записи по имени нужны только `w` и `x`.
53. *Почему `rm -f`?* Файлы без `w` — `rm` спросил бы подтверждение; `-f` убирает вопрос.
54. *Что удалил `rm Copy_*`?* Только символическую ссылку.
55. *Где оказалась копия в `cp -r chinchou pansear/pidgeotto`?* В `pansear/pidgeotto/chinchou`, потому что `pidgeotto` уже существовал.
56. *Как в 4.2 получить «по убыванию даты изменения записи»?* `-t` + `-c`.
57. *Как в 4.6 получить «по возрастанию размера»?* `-S` + `-r`.
58. *Зачем `sh -x`?* Трассировка: печатает каждую команду перед выполнением.

Всё ниже собрано из интернета (ссылки в конце раздела). Особенно важны подразделы про **FreeBSD**: helios работает именно на ней, и преподаватель может попросить что-то показать прямо там.

### 17.1. История UNIX подробнее
- В 1960-х Bell Labs вместе с MIT и General Electric делала большую ОС **Multics**. В **1969** Bell Labs из проекта вышла: он был слишком сложным и не приносил денег.
- Кен Томпсон и Деннис Ритчи написали маленькую систему для мини-компьютера **PDP-7**. Название **Unics** (потом UNIX) — шутка-противопоставление громоздкой Multics.
- **1972** — вторая редакция (часть переписана на языке B). **1973** — третья редакция, в ней появились **конвейеры**. **15 октября 1973** — четвёртая редакция с ядром на **C**. Это главный момент: ОС на языке высокого уровня можно переносить на другие машины (PDP-11 и дальше).
- С **1978** код расходится на две ветви: **BSD** (Калифорнийский университет в Беркли; там в 1980-х появился стек **TCP/IP**) и коммерческая **System V** от AT&T (1983).
- **POSIX** (1988) — стандарт совместимости UNIX-систем от IEEE. **Single UNIX Specification** — современный стандарт, по которому систему сертифицируют. Торговая марка **UNIX** принадлежит **The Open Group**: официально «UNIX» называется только сертифицированная система (например, macOS), а Linux и FreeBSD формально «UNIX-подобные».
- **Linux** (1991) — свободное ядро, написанное заново, без кода AT&T.
- Отличительные черты UNIX: **многопользовательская** и **многозадачная** система, **иерархическая** файловая система с одним корнем, ориентация на **текстовые** данные, **конвейеры**.

### 17.2. Философия UNIX
Три принципа **Дугласа Макилроя** (автора идеи конвейеров):
1. Пишите программы, которые делают **одну вещь**, и делают её хорошо.
2. Пишите программы, которые **работают вместе**.
3. Пишите программы, которые работают с **текстовыми потоками**, потому что текст — универсальный интерфейс.

Это прямо объясняет лабу: вместо одной огромной программы «найди файлы на n, отсортируй по размеру и покажи три последних» есть маленькие `ls`, `grep`, `sort`, `tail`, и ты собираешь из них конвейер. Эрик Рэймонд позже свёл философию к принципу **KISS** (Keep It Simple, Stupid): модульность, ясность, композиция, простота.

### 17.3. Конвейер изнутри
- Идею продвигал Макилрой, **Кен Томпсон реализовал её в 1973 году** в третьей редакции UNIX: добавил системный вызов `pipe()` и запись `|`. Макилрой вспоминал, что сделано это было за «одну лихорадочную ночь».
- Как shell строит `a | b`:
  1. вызов `pipe()` создаёт **канал** — буфер в ядре с двумя дескрипторами: один для записи, другой для чтения;
  2. `fork()` дважды — два дочерних процесса;
  3. в первом `dup2()` делает дескриптор **1** (stdout) копией конца канала для записи, во втором дескриптор **0** (stdin) — копией конца для чтения;
  4. `exec` — в процессах запускаются `a` и `b`.
- Обе программы работают **одновременно**. Буфер канала ограничен (в Linux обычно 64 КиБ): если `b` не успевает читать и буфер полон, `a` **ждёт**; если буфер пуст, ждёт `b`.
- Если читатель завершился раньше (например, `head` уже прочитал нужные строки), писатель получает сигнал **SIGPIPE** и тоже завершается. Поэтому `yes | head -n 3` не работает вечно.
- В sh каждая команда конвейера выполняется в отдельном **подпроцессе** (subshell). Поэтому `cd /tmp | ls` не сменит каталог текущего shell.
- **Код возврата** конвейера — код последней команды. `! a | b` — инвертировать результат. В bash есть `set -o pipefail`: тогда код будет ненулевым, если упала любая команда.
- **Неименованный канал** (`|`) существует, пока живут процессы. **Именованный канал (FIFO)** — файл типа `p` в дереве, создаётся `mkfifo`, через него могут общаться процессы, которые ничего друг о друге не знают:
```bash
mkfifo /tmp/s561306_fifo
ls -l /tmp/s561306_fifo            # prw-r--r-- ... тип p
cat /tmp/s561306_fifo &            # читатель ждёт в фоне
echo "привет через FIFO" > /tmp/s561306_fifo
rm /tmp/s561306_fifo
```

### 17.4. Все перенаправления sh (из `man sh` на FreeBSD)
`n` — номер дескриптора, если не указан, берётся 0 для `<` и 1 для `>`.

| Запись | Смысл |
|---|---|
| `[n]> f` | вывод дескриптора n в файл (перезапись) |
| `[n]>\| f` | то же, но **игнорируя noclobber** |
| `[n]>> f` | дописать в файл |
| `[n]< f` | ввод из файла |
| `[n]<> f` | открыть файл **и на чтение, и на запись** |
| `[n1]<&n2` | ввод n1 — копия дескриптора n2 |
| `[n1]>&n2` | вывод n1 — копия дескриптора n2 (`2>&1`) |
| `[n]<&-`, `[n]>&-` | **закрыть** дескриптор (`2>&-` — программа вообще не сможет писать ошибки) |
| `<< EOF` | here-document |
| `<<- EOF` | here-document, у строк которого убираются ведущие **табуляции** (удобно для отступов в скриптах) |

- **noclobber**: `set -C` запрещает `>` перезаписывать существующие файлы (защита от случайной потери данных). Обойти — `>|`.
- Порядок: сначала shell подключает **конвейер**, потом выполняет перенаправления **слева направо**. Поэтому `cmd 2>&1 | grep` отправляет ошибки в трубу (это твои 4.3 и 4.4).
- Перенаправления можно поставить в любое место команды: `> f echo hi` тоже работает.
- `exec > log 2>&1` в начале скрипта — перенаправить потоки **всего** скрипта.

### 17.5. Порядок обработки строки в sh (точнее, чем в разделе 2)
1. Одновременно: **тильда** (`~`), **параметры** (`$x`), **подстановка команд** (`$(cmd)`), **арифметика** (`$((2+3))`).
2. **Разбиение на поля** по пробелам (переменная `IFS`), но только результатов подстановок без кавычек.
3. **Раскрытие путей** (glob `*`, `?`, `[...]`). `set -f` его отключает.
4. **Удаление кавычек**.

Поэтому `x="*"; echo $x` выведет список файлов (подставилось, потом раскрылось), а `echo "$x"` — звёздочку.

Специальные параметры: `$?` — код возврата последнего конвейера, `$$` — PID shell, `$!` — PID последнего фонового процесса, `$0` — имя скрипта, `$1`…`$9` — аргументы скрипта, `$#` — их количество.

Полезные опции shell (ставятся `set -x` или `sh -x script`):
- `-x` (xtrace) — печатать каждую команду в **stderr** перед выполнением, с префиксом из переменной `PS4` (по умолчанию `+ `). Обрати внимание: трассировка идёт в stderr, а не в stdout.
- `-e` (errexit) — завершить скрипт при первой неудачной команде.
- `-C` (noclobber), `-f` (без раскрытия шаблонов), `-u` (ошибка при обращении к неопределённой переменной).

### 17.6. Буферизация stdout и stderr
- **stdout буферизован**: если вывод идёт в терминал, данные отдаются построчно; если в файл или в канал, накапливаются блоками (несколько КиБ) и уходят, когда буфер заполнился или программа завершилась.
- **stderr не буферизован**: каждое сообщение уходит сразу. Ошибка должна появиться немедленно, даже если программа тут же упадёт.
- Следствие: при `cmd > f 2>&1` или `cmd 2>&1 | ...` строки ошибок и данных могут оказаться **не в том порядке**, в каком программа их «печатала». Если на защите спросят, почему в выводе 4.3 ошибки стоят не там, где ожидалось, отчасти поэтому (а в 4.3 ещё и `sort -r` всё перемешал).
- Цель stderr **не меняется**, когда пользователь пишет `>` или `|`. В этом весь смысл отдельного потока ошибок.
- В языке C потоки доступны как `stdin`, `stdout`, `stderr` (и дескрипторы `STDIN_FILENO` = 0, `STDOUT_FILENO` = 1, `STDERR_FILENO` = 2). Функция `perror()` печатает в stderr текст последней ошибки (по `errno`). Сообщения вроде `Permission denied` — это как раз текст ошибки `EACCES`.

### 17.7. inode: дополнительные факты
- Номер inode **не меняется** при переименовании и перемещении файла внутри той же ФС (`mv` трогает только каталоги).
- **inode могут закончиться**: в ФС с фиксированной таблицей inode (UFS, ext2–ext4) нельзя создать новый файл, даже если место на диске есть. В ZFS (helios), XFS, Btrfs inode выделяются динамически. Посмотреть занятость inode: `df -i`.
- **Удаление открытого файла:** если `rm` убрал последнее имя, а какой-то процесс ещё держит файл открытым, данные **не освобождаются**, пока процесс его не закроет. Отсюда классическая загадка «удалил большой лог, а место не освободилось».
- **Время создания в FreeBSD.** Классический UNIX хранил только atime, mtime, ctime. Но UFS2 и ZFS в FreeBSD хранят ещё **birth time** (время создания): `ls -lU` показывает и сортирует по нему, `stat` тоже его выводит. На Linux этого ключа у `ls` нет. Поэтому правильный ответ на защите: «ctime — это **не** время создания, а время изменения inode; время создания в классическом UNIX не хранилось, а FreeBSD его хранит отдельно».
```bash
stat bagon        # на FreeBSD: все поля inode, включая четыре времени
stat -x bagon     # то же в развёрнутом виде, как в Linux
ls -lU            # время создания (FreeBSD)
```

### 17.8. `ls` на FreeBSD: что ещё может спросить преподаватель
Ключи, которых не было в разделе 8:

| Ключ | Смысл |
|---|---|
| `-U` | время **создания** (birth time) |
| `-T` | полное время, с секундами и годом |
| `-D формат` | своё форматирование даты: `ls -lD "%Y-%m-%d %H:%M:%S"` |
| `-o` | показать **флаги файла** (chflags, см. 17.10) |
| `-s` | сколько блоков занимает каждый файл |
| `-k` | размер блока 1024 байта |
| `-f` | не сортировать (порядок, в котором записи лежат в каталоге) |
| `-p` | `/` после каталогов |
| `-g` | на FreeBSD — длинный формат без владельца |
| `-G` | цветной вывод |
| `-L` | для ссылки показать информацию о **цели**, а не о самой ссылке |
| `-H` | следовать по ссылкам, указанным в командной строке |

- `-F` на FreeBSD добавляет: `/` каталог, `*` исполняемый, `@` символическая ссылка, `=` сокет, `|` FIFO, `%` whiteout.
- Если сразу после 9 символов прав стоит **`+`**, у файла есть **ACL** (расширенный список доступа, где можно дать права конкретным пользователям сверх u/g/o).
- Первый символ может быть ещё `w` — **whiteout** (служебная запись union-файловых систем), на практике не встретишь.
- В правах третья позиция тройки может быть `s`/`S` (SUID/SGID с x/без x) и `t`/`T` (sticky с x/без x).

### 17.9. `chmod` полностью (из `man chmod` FreeBSD)
**Абсолютный режим** — сумма восьмеричных чисел:

| Число | Значение |
|---|---|
| 4000 | SUID |
| 2000 | SGID |
| 1000 | sticky |
| 0400 / 0200 / 0100 | владелец r / w / x |
| 0040 / 0020 / 0010 | группа r / w / x |
| 0004 / 0002 / 0001 | остальные r / w / x |

Отсюда 755 = 400+200+100+40+10+4+1. Твои `004` и `400` — это ровно одна строка таблицы.

**Символьный режим:** `[кто][операция][права]`, через запятую.
- кто: `u`, `g`, `o`, `a`;
- операция: `+`, `-`, `=`;
- права: `r`, `w`, `x`, а также:
  - `X` — поставить x, **только если это каталог или у файла уже есть x у кого-нибудь**. Классика: `chmod -R a+rX dir` — всем дать читать файлы и заходить в каталоги, но не делать обычные файлы исполняемыми;
  - `s` — SUID/SGID (`chmod u+s`, `chmod g+s`);
  - `t` — sticky (`chmod +t dir`);
  - `u`, `g`, `o` — **скопировать** права другой категории: `chmod g=u f` — группе то же, что у владельца; `chmod o=g f`.
- Если **кто не указан** (`chmod +x f`), изменение делается для всех, но **с учётом umask**: при umask 022 `chmod +w f` добавит w только владельцу.
- `=` сначала сбрасывает указанные категории, потом ставит заданное: `chmod u= f` — владелец без прав.

Ключи FreeBSD:
- `-R` — рекурсивно; с ним `-H` (идти по ссылкам из командной строки), `-L` (по всем ссылкам), `-P` (не идти, по умолчанию);
- `-h` — менять права **самой символической ссылки**, а не цели (в FreeBSD у ссылки есть свои права, через `lchmod`; на Linux так нельзя);
- `-v` — печатать имена изменённых файлов, `-vv` — ещё и старые и новые права;
- `-f` — не печатать ошибки.

Связанные команды: `chown пользователь[:группа] файл` (сменить владельца, обычному пользователю нельзя), `chgrp группа файл` (сменить группу на одну из своих).

### 17.10. Флаги файлов FreeBSD (`chflags`)
Кроме прав rwx в FreeBSD есть **флаги**, которые проверяются отдельно:
- `uchg` — пользовательский «неизменяемый» флаг: файл нельзя менять, переименовывать и удалять, даже владельцу, пока флаг не снят;
- `uunlnk` — нельзя удалить;
- `schg`, `sunlnk` — системные варианты, ставит только root, и **даже root** не сможет удалить файл (при повышенном уровне безопасности ядра флаг не снять без перезагрузки);
- `nodump`, `hidden` и другие.
```bash
chflags uchg f      # поставить
ls -lo f            # увидеть флаги (столбец после группы)
rm f                # Operation not permitted
chflags nouchg f    # снять (приставка no)
```
Если на защите спросят «как сделать файл, который не удалит даже владелец» — это ответ для FreeBSD. Права rwx этого не дают: владелец всегда может вернуть себе права через `chmod`.

### 17.11. umask подробно
- Каждый **процесс** имеет свою umask, дочерние процессы её **наследуют** (поэтому umask shell действует на все команды, которые он запускает).
- Применяется операцией **«И-НЕ»**: итоговые права = запрошенные **AND NOT** umask. Бит, стоящий в маске, **запрещает** право.
- Маска влияет **только на создание** новых файлов, существующие не трогает.
- Новые обычные файлы почти всегда создаются без x, независимо от маски.

| umask | Файлы (из 666) | Каталоги (из 777) | Смысл |
|---|---|---|---|
| 000 | 666 `rw-rw-rw-` | 777 | никаких ограничений |
| 002 | 664 `rw-rw-r--` | 775 | группа может писать (совместная работа) |
| 022 | 644 `rw-r--r--` | 755 | стандарт: писать только владельцу |
| 027 | 640 `rw-r-----` | 750 | остальным ничего |
| 077 | 600 `rw-------` | 700 | только владелец |

```bash
umask           # текущая маска числом, например 0022
umask -S        # в буквах — какие права РАЗРЕШЕНЫ: u=rwx,g=rx,o=rx
umask 077       # сменить для текущего shell
```
⚠️ Цифры маски «обратные»: в маске `2` значит «запретить w», а в правах `2` значит «разрешить w». `umask -S` показывает уже разрешённые права.

### 17.12. `ln` на FreeBSD
- Без ключей — жёсткая ссылка; `-s` — символическая.
- `-f` — если имя занято, сначала удалить его; `-i` — спросить; `-v` — печатать, что сделано.
- `-h` / `-n` — если имя назначения — символическая ссылка на каталог, не заходить внутрь, а заменить саму ссылку (нужно вместе с `-f`, чтобы перенаправить существующую ссылку на другую цель).
- `-w` — предупредить, если цель символической ссылки не существует (сам `ln -s` по умолчанию молча создаёт и висячие ссылки).
- `-L` / `-P` — при создании **жёсткой** ссылки на символическую: ссылаться на цель или на саму ссылку.
- Формы: `ln цель имя`, `ln цель` (имя как у цели, в текущем каталоге), `ln цель... каталог`.
- Есть простейшая команда **`link a b`** — ровно системный вызов `link()`, без ключей.
- Пример из системы: `/bin/[` и `/bin/test` — **жёсткие ссылки на один файл**. Программа смотрит, под каким именем её запустили (`$0`), и ведёт себя чуть по-разному. Проверь: `ls -li /bin/[ /bin/test`.

### 17.13. `rm` на FreeBSD
- Без ключей не удаляет каталоги. `-d` — удалять и пустые каталоги (как `rmdir`). `-r`/`-R` — рекурсивно (включает `-d`).
- `-f` — не спрашивать и не ругаться на несуществующие файлы; код возврата 0, даже если файла не было.
- `-i` — спрашивать про каждый файл; `-I` — спросить **один раз**, если удаляется больше трёх файлов или идёт рекурсия (защита от `rm -r` по ошибке).
- `-v` — печатать удаляемые имена. `-x` — не переходить в другие смонтированные ФС. `-P` — устарел, ничего не делает.
- Если у файла нет права записи и stdin — терминал, `rm` **спрашивает** подтверждение. Это поведение самой команды, а не запрет ядра.
- В каталоге со **sticky-битом** (`/tmp`) удалить файл может только его владелец, владелец каталога или root.
- Символическую ссылку `rm` удаляет **саму**, цель не трогает.
- Удалить `/`, `.` или `..` `rm` откажется.
- Команда **`unlink f`** — ровно системный вызов `unlink()`: один файл, без ключей.

### 17.14. `cp` на FreeBSD
- Рекурсивное копирование — **`-R`**. `-r` поддерживается для совместимости, но man советует `-R`.
- `-p` — сохранить время изменения и доступа, флаги, права, ACL, владельца и группу (владельца сохранить может только root).
- `-a` — режим архива, то же что `-RpP`.
- `-f` — удалять мешающий файл без вопросов; `-i` — спрашивать; `-n` — **не перезаписывать** существующие.
- `-l` — вместо копии сделать **жёсткую ссылку**, `-s` — **символическую**.
- `-v` — печатать пары «откуда → куда». `-x` — не выходить за пределы ФС.
- `-H`, `-L`, `-P` — как обращаться с символическими ссылками при `-R` (по умолчанию `-P`: копируется сама ссылка).
- Жёсткие ссылки внутри копируемого дерева превращаются в **отдельные файлы**. Чтобы их сохранить, используют `tar`, `cpio` или `pax`.
- Без `-p` SUID/SGID могут быть **сброшены** у копии (иначе любой мог бы скопировать чужую SUID-программу и запускать её с правами автора).
- Права копии — права исходника с учётом umask, владелец — тот, кто копирует.

### 17.15. Процессы и сигналы (на случай вопросов «а что ещё умеет shell»)
- **Демон** — фоновый процесс без терминала, который предоставляет службу (sshd, через который ты заходишь на helios, cron, веб-сервер).
- Посмотреть процессы: `ps aux` (все, с владельцем, CPU и памятью), `top` (в реальном времени, выход `q`).
- **Сигнал** — асинхронное уведомление процессу:

| Сигнал | № | Что делает | Откуда |
|---|---|---|---|
| SIGINT | 2 | прервать | `Ctrl+C` |
| SIGQUIT | 3 | прервать с дампом памяти | `Ctrl+\` |
| SIGKILL | 9 | убить, перехватить **нельзя** | `kill -9 PID` |
| SIGTERM | 15 | вежливо попросить завершиться (по умолчанию у `kill`) | `kill PID` |
| SIGTSTP | 18 (FreeBSD) | приостановить с терминала | `Ctrl+Z` |
| SIGSTOP / SIGCONT | 17 / 19 (FreeBSD) | остановить / продолжить | `kill -STOP`, `kill -CONT` |
| SIGPIPE | 13 | писать в канал, который никто не читает | конвейер |
| SIGHUP | 1 | терминал закрылся | разрыв ssh |

- Управление заданиями: `cmd &` — в фоне, `jobs` — список, `fg %1` — на передний план, `bg %1` — продолжить в фоне, `Ctrl+Z` — приостановить текущее.
- Номера сигналов на разных системах могут отличаться, кроме классических 1, 2, 3, 9, 15. Список: `kill -l`.

### 17.16. Устройства, диски, монтирование (FreeBSD)
- Устройства — файлы в `/dev`. Имена дисков FreeBSD: `ada0` (SATA), `da0` (SCSI и USB), `nvd0`/`nda0` (NVMe), `cd0` (CD-ROM). Разделы: `ada0p1` (GPT) или `ada0s1a` (MBR: слайс 1, раздел a).
- Чтобы файлы на устройстве стали видны, ФС **монтируют** в существующий каталог: содержимое каталога заменяется корнем этой ФС. Список автоматически монтируемых ФС — `/etc/fstab`. `mount` без аргументов показывает, что смонтировано, `df -h` — свободное место.
- Опция монтирования `nosuid` выключает SUID/SGID на этой ФС, `ro` — только чтение.
- Полное описание дерева каталогов FreeBSD: `man hier`.

### 17.17. Пользователи в FreeBSD
- Три вида учётных записей: **системные** (под ними работают службы, чтобы взлом службы не дал прав root), **пользовательские** (люди), **суперпользователь** root.
- `/etc/passwd` — имя, UID, GID, домашний каталог, shell (пароли в FreeBSD хранятся отдельно, в `/etc/master.passwd`, который читает только root). `/etc/group` — группы и их участники.
- Сменить свой shell: `chsh`. Пароль: `passwd`.

### 17.18. man подробнее
Разделы руководства: **1** — команды пользователя, **2** — системные вызовы, **3** — функции библиотек, **4** — драйверы, **5** — форматы файлов (`man 5 passwd`), **6** — игры, **7** — разное (`man 7 hier`), **8** — администрирование. Поиск по ключевому слову: `man -k слово` (то же, что `apropos`).

### 17.19. Ещё вопросы к защите (дополнение к разделу 16)
59. *Кто и когда придумал конвейер?* Идея Дугласа Макилроя, реализовал Кен Томпсон в 1973 году (3-я редакция UNIX).
60. *Сформулируй философию UNIX.* Три принципа Макилроя (17.2).
61. *Как shell технически создаёт конвейер?* `pipe()`, `fork()`, `dup2()`, `exec()`.
62. *Что будет, если читатель конвейера завершится раньше писателя?* Писатель получит SIGPIPE.
63. *Чем неименованный канал отличается от именованного?* Именованный (FIFO, тип `p`) — файл в дереве, создаётся `mkfifo`, им могут пользоваться независимые процессы.
64. *Почему stderr не буферизуется?* Чтобы сообщение об ошибке появилось сразу, даже если программа тут же завершится аварийно.
65. *Почему вывод при `2>&1` может идти «вперемешку»?* stdout буферизован, stderr нет.
66. *Что делает `>|` и `set -C`?* noclobber: запрет перезаписи через `>`; `>|` его обходит.
67. *Как закрыть поток?* `2>&-`.
68. *Куда пишет трассировка `sh -x`?* В stderr, с префиксом `+`.
69. *Что значит `$?`, `$$`, `$!`?* Код возврата, PID shell, PID последнего фонового процесса.
70. *В каком порядке shell раскрывает строку?* Подстановки → разбиение на поля → шаблоны путей → удаление кавычек.
71. *Может ли кончиться место для файлов при свободном диске?* Да, если кончились inode (UFS, ext4).
72. *Что будет, если удалить файл, который открыт процессом?* Имя исчезнет, данные — только когда процесс закроет файл.
73. *Хранит ли FreeBSD время создания?* Да (birth time), `ls -lU`, `stat`. ctime — не оно.
74. *Что значит `+` после прав в `ls -l`?* У файла есть ACL.
75. *Что значат `s`, `S`, `t`, `T` в правах?* SUID/SGID и sticky, заглавная — когда под ними нет x.
76. *Что делает `chmod a+X`?* x только каталогам и уже исполняемым файлам.
77. *Что делает `chmod g=u f`?* Копирует права владельца в группу.
78. *Что будет при `chmod +w f` без указания кому?* Добавится w с учётом umask (при 022 — только владельцу).
79. *Как сделать файл, который не может удалить даже владелец?* В FreeBSD — `chflags uchg` (или `schg` от root). Одними правами rwx нельзя.
80. *Как работает umask?* Права = запрошенные AND NOT маска; наследуется процессами; влияет только на новые файлы.
81. *Почему `/bin/[` и `/bin/test` — одно и то же?* Это жёсткие ссылки на один inode.
82. *Чем `rm -i` отличается от `rm -I`?* `-i` спрашивает про каждый файл, `-I` один раз для массового удаления.
83. *Что такое sticky-бит на `/tmp`?* Удалять файл может только его владелец (или владелец каталога, root).
84. *Почему у копии может пропасть SUID?* Защита: иначе любой копировал бы чужие привилегированные программы.
85. *Как скопировать файл, сохранив права и время?* `cp -p`; дерево целиком — `cp -a`.
86. *Чем SIGTERM отличается от SIGKILL?* TERM можно перехватить и корректно завершиться, KILL перехватить нельзя.
87. *Что такое демон?* Фоновый процесс без терминала, предоставляющий службу (sshd).
88. *Что такое монтирование?* Подключение ФС устройства к каталогу общего дерева.
89. *Что такое POSIX и чем UNIX отличается от UNIX-подобной ОС?* Стандарт совместимости; «UNIX» — торговая марка, ей называются только сертифицированные системы.
90. *Какие разделы есть у man?* 1 команды, 2 системные вызовы, 3 библиотеки, 5 форматы файлов, 8 администрирование и др.

## Ответы к упражнениям

<details>
<summary>Упр. 2 и 2б</summary>

`ls . nope 2> /tmp/err_$USER` — содержимое на экране, ошибка в файле.
`ls . nope > /tmp/all_$USER 2>&1` — всё в файл.

`> out 2>&1`: сначала 1 → out, затем 2 → туда же, оба потока в файле.
`2>&1 > out`: сначала 2 → куда сейчас 1 (экран), затем 1 → out. Ошибка на экране, список в файле.
</details>

<details>
<summary>Упр. 4 и 4б</summary>

«привет» — 6 букв по 2 байта = 12 байт; `echo` добавляет `\n` (1 байт, 1 символ). Итого `wc -c` = 13, `wc -m` = 7.

`sort f`: `10`, `100`, `2`, `9` (посимвольно). `sort -n f`: `2`, `9`, `10`, `100`. `sort -nr f`: `100`, `10`, `9`, `2`.
</details>

<details>
<summary>Упр. 5 и 5б</summary>

`rwxr-x---` = 750 · `-wxr-xrwx` = 357 · `r--r-----` = 440 · `------r--` = 004

`355` = `-wxr-xr-x` = `u=wx,g=rx,o=rx` · `771` = `rwxrwx--x` = `ug=rwx,o=x` · `305` = `-wx---r-x` = `u=wx,g=,o=rx` · `711` = `rwx--x--x` = `u=rwx,go=x`
</details>

<details>
<summary>Упр. 6 и 6б</summary>

Без `r` на `d`: `ls d` — Permission denied, но `cat d/f` работает (имя известно, `x` есть). Без `x`: `cat d/f` — Permission denied, внутрь не попасть.

`d2` = `-wx------`: удалить `d2/f` **можно** (`rm -f d2/f`), потому что есть `w` и `x` на каталог, а права файла не важны. Увидеть список (`ls d2`) нельзя — нет `r`. Верни права: `chmod 700 d2`, потом `rm -r d2`.
</details>

<details>
<summary>Упр. 7</summary>

У `x` и `xh` одинаковый номер inode и счётчик 2, у `xs` свой inode и тип `l`. После `rm x`: `cat xh` выводит текст, `cat xs` — No such file or directory. После создания нового `x` ссылка `xs` снова работает, но показывает **новый** текст: она хранит путь, а не inode.
</details>
