# 04. Защита: ответы на контрольные вопросы

Вопросы взяты из методички (с. 6). Их всего четыре, но первый — «расскажите про команду X», и X может быть **любой** командой из лабы. Поэтому ниже есть карточка для каждой.

## 1. «Расскажите про команду …»
Схема ответа: **что делает → синтаксис и главные ключи → сколько аргументов и какие → фильтр или нет → пример из лабы**.

**Фильтр** — команда, которая может читать данные со **stdin**, обрабатывать их и писать результат в **stdout**, поэтому её можно ставить в середину конвейера `a | ФИЛЬТР | b`. Фильтры: `cat`, `grep`, `sort`, `head`, `tail`, `wc`, `more` (с оговоркой: он интерактивный). **Не** фильтры (не читают stdin): `ls`, `echo`, `mkdir`, `touch`, `cp`, `mv`, `rm`, `rmdir`, `ln`, `chmod`, `cd`, `pwd`.

| Команда | Синтаксис и ключи | Аргументы | Фильтр? | В лабе |
|---|---|---|---|---|
| `mkdir` | `mkdir [-m mode] [-p] dir...` — `-p` создать родительские, `-m` сразу задать права | 1 и больше имён каталогов | нет | создание дерева |
| `echo` | `echo [string]...` — печатает аргументы через пробел в stdout | 0 и больше строк | нет (stdin не читает) | запись содержимого через `>` и `>>` |
| `cat` | `cat [-n] [file...] [-]` — склеить файлы и вывести; `-n` номера строк; без файлов или с `-` читает stdin | 0 и больше файлов | **да** | `zoroark_57`, 4.3, 4.4 |
| `touch` | `touch [-am] file...` — обновить время доступа или изменения, создать пустой файл | 1 и больше | нет | можно создавать файлы |

## 2. Стандартные потоки ввода-вывода
**Коротко:** у каждого процесса три открытых потока: **stdin (0)** — ввод, по умолчанию с клавиатуры; **stdout (1)** — вывод, по умолчанию на экран; **stderr (2)** — сообщения об ошибках, тоже на экран, но отдельным каналом, чтобы ошибки не смешивались с данными.

**Управление в shell:**
- `>` и `>>` — stdout в файл (перезаписать / дописать);
- `2>` и `2>>` — stderr в файл;
- `2>&1` — направить stderr туда же, куда сейчас идёт stdout;
- `<` — взять stdin из файла; `<<EOF` — «here-document», ввод до строки `EOF`;
- `|` — конвейер: stdout одной команды становится stdin следующей;
- `/dev/null` — «чёрная дыра», туда выбрасывают ненужный вывод.

**Пример из лабы:** в 4.2 `2>/tmp/…` уводит `Permission denied` в файл, а данные идут по конвейеру в `grep`. В 4.4 `2>&1` стоит **до** `|`, поэтому ошибки попадают в конвейер вместе с данными.

## 3. Права доступа, `chmod`, вывод `ls -l`
**Коротко:** права задаются для трёх категорий: владелец (u), группа-владелец (g), остальные (o). Прав три: r, w, x.

- Для **файла**: r — читать, w — изменять, x — запускать.
- Для **каталога**: r — получать список имён, w — создавать, удалять и переименовывать записи (вместе с x), x — входить и обращаться к объектам по имени.

**Способы задания:**
- **восьмеричный**: r=4, w=2, x=1, сумма по каждой тройке (`chmod 751 d` → `rwxr-x--x`);
- **символьный**: `chmod [ugoa][+-=][rwx]` (`chmod u+x,go-w f`, `chmod o= f`).

**`ls -l`:** `-rw-r--r-- 2 s561306 studs 76 Sep 28 12:00 bagon`: тип (`-` файл, `d` каталог, `l` ссылка) + 9 символов прав, число жёстких ссылок, владелец, группа, размер в байтах, дата изменения, имя. У символической ссылки в конце `-> цель`.

**Тонкие моменты** (любят спрашивать):
- удалить файл можно и без прав на сам файл, если есть **w и x на каталог**;
- без **r** на каталог `ls` не работает, но зная имя, можно открыть файл внутри, если есть **x**;
- без **x** на каталог внутрь не попасть вообще, даже если есть r;
- `root` игнорирует права;
- у новых файлов права задаёт **umask** (обычно 022: файлы 644, каталоги 755).

**Пример из лабы:** у `pansear` права 551, поэтому для `ln` в п. 3 и `rm` в п. 5 пришлось временно делать `chmod u+w pansear`.

## 4. Файлы в UNIX, типы, ссылки
**Принцип «всё есть файл»:** устройства, каналы и сокеты тоже представлены файлами.

**Типы** (первый символ в `ls -l`): `-` обычный файл · `d` каталог · `l` символическая ссылка · `c` символьное устройство (например `/dev/tty`) · `b` блочное устройство (диск) · `p` именованный канал (FIFO) · `s` сокет.

**inode** — служебная запись о файле: права, владелец, размер, время, где лежат данные. **Имени в inode нет**, имя хранится в каталоге как пара «имя → номер inode».

**Жёсткая ссылка** (`ln`) — ещё одна запись «имя → тот же inode».
- Все имена равноправны. Файл удаляется, только когда исчезает последнее имя (счётчик ссылок в `ls -l` = 0).
- Работает только в пределах одной файловой системы.
- На каталоги делать нельзя (кроме служебных `.` и `..`).
- Права общие, потому что inode один. 💡 В лабе `bagon` и `cranidosbagon` показывают одинаковые права, размер и счётчик **2**.

**Символическая ссылка** (`ln -s`) — отдельный маленький файл, внутри которого записан путь к цели.
- Может указывать на каталог и на другую файловую систему.
- Если цель удалить, ссылка «висит» (dangling). 💡 В лабе после `rm bagon` ссылка `raltsbagon` повиснет, а `cranidosbagon` продолжит работать.
- Относительный путь в ней считается от каталога, где лежит **сама ссылка**.
- Права самой ссылки `lrwxrwxrwx` ни на что не влияют, проверяются права цели.
