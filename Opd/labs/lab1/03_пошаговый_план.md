# 03. Делаем лабу по шагам

Работаем так же, как с лабой по программированию. Ты пишешь команды в скрипт `lab0.sh`, запускаешь на helios и смотришь результат. Под каждым шагом спрятана подсказка, открывай её, только если застрял. Все подсказки я проверил на обычном пользователе без прав root.

**Как устроен скрипт.** Пиши его частями: `part1.sh` (дерево и права), `part3.sh` (ссылки и копии), `part4.sh` (поиск), `part5.sh` (удаление). Или одним файлом с комментариями `# --- 1 ---`. Для отчёта нужен итоговый полный файл.

**Как начать заново, если что-то пошло не так:**
```bash
cd ~ && chmod -R u+rwx lab0 && rm -rf lab0
```
`chmod -R u+rwx` нужен потому, что с закрытыми правами `rm -rf` может не удалить всё.

---

## Шаг 1. Дерево (≈30 мин)
1. `cd ~`, `mkdir lab0`, `cd lab0`.
2. Создай все **каталоги** командой `mkdir`. Можно несколько сразу: `mkdir chinchou chinchou/duskull ...`.
3. Создай **файлы** с содержимым: первую строку через `echo "..." > файл`, следующие через `echo "..." >> файл`.
4. Проверь: `ls -lR` и `cat` каждого файла. Сверь с таблицей из `00_задание`.

<details><summary>Подсказка: пример для двух файлов</summary>

```bash
echo "Возможности = Overland=6 Surface=4" > bagon
echo "Jump=3 Power=2 Intelligence=3" >> bagon
echo "Способности = Dark Art Illusion" > zoroark
echo "Prankster" >> zoroark
```
</details>

## Шаг 2. Права (≈30 мин)
1. Заполни таблицу из `02_права_тренажёр.md`.
2. Пиши `chmod`, **чередуя** числовой и символьный способы: в задании прямо сказано «используя различные способы указания прав».
3. Порядок: сначала файлы и вложенные каталоги, **потом** родительские `chinchou`, `pansear`, `scizor`.
4. Проверь `ls -lR`. Появятся строки `Permission denied`: это нормально, так и задумано.

<details><summary>Подсказка: образцы обоих способов</summary>

```bash
chmod 004 bagon                    # числом
chmod u=wx,g=rx,o=rwx chinchou      # символами
chmod ug=rw,o= chinchou/psyduck     # символами: o= значит «ничего»
```
</details>

## Шаг 3. Ссылки и копии (≈40 мин)
Выполняй **по одной** команде и после каждой смотри на ошибку, если она появилась. Для отчёта нужно записать: команду, ошибку и исправление.

| Подзадача | Команда-основа | Какая ловушка |
|---|---|---|
| symlink `Copy_66` → `pansear` | `ln -s` | путь цели относительно `lab0` |
| `metagross` + `metagross` → `zoroark_57` | `cat ... > ...` | нет |
| `zoroark` → `scizor/furret` | `cp` | нет |
| symlink `pansear/raltsbagon` → `bagon` | `ln -s` | 1) у `pansear` нет **w**; 2) путь цели от папки ссылки: `../bagon` |
| содержимое `bagon` → `scizor/wynautbagon` | `cat bagon > ...` | у `bagon` нет **r** для владельца |
| жёсткая ссылка `pansear/cranidosbagon` → `bagon` | `ln` | у `pansear` нет **w** |
| `chinchou` рекурсивно → `pansear/pidgeotto` | `cp -r` | у `chinchou`, `duskull`, `starmie` нет **r** |

После каждого исправления **верни права обратно**, как требует методичка. Когда п. 3 выполнен, сделай снимок для отчёта:
```bash
cd ~/lab0 && ls -lR > ~/tree_after_3.txt 2>&1
```

<details><summary>Подсказка: как выглядит «исправление» в скрипте</summary>

```bash
chmod u+w pansear                 # временно даём себе право писать в pansear
ln -s ../bagon pansear/raltsbagon
ln bagon pansear/cranidosbagon
chmod u-w pansear                 # возвращаем как было (r-xr-x--x)

chmod u+r bagon
cat bagon > scizor/wynautbagon
chmod u-r bagon
```
С `cp -r chinchou` то же самое: временно добавить `u+r` трём каталогам, скопировать, убрать. У **копий** внутри `pidgeotto` права лучше тоже привести к исходным, чтобы копия совпадала с оригиналом.
</details>

## Шаг 4. Поиск и фильтрация (≈40 мин)
Разбери каждое предложение задания на части: **что выводим** → **какой фильтр** → **как сортируем** → **сколько оставить** → **куда ошибки**.

| № | Скелет конвейера | Что уточнить |
|---|---|---|
| 4.1 | `wc -m chinchou/* 2>/tmp/… \| sort -n` | почему шаблон `chinchou/*` может не раскрыться? (см. раздел 7 в `01`) |
| 4.2 | `ls -lR… 2>/tmp/… \| grep "pi" \| tail -n 2` | какие ключи `ls` дают «по убыванию даты **изменения записи** о файле»? (`-t` и `-c`) |
| 4.3 | `cat -n <шаблоны на *t> 2>&1 \| sort -r` | «рекурсивно» без `find`: шаблоны `*t */*t */*/*t` |
| 4.4 | `cat -n zoroark 2>&1 \| grep -i "ce"` | не удивляйся результату |
| 4.5 | `ls -lR 2>/tmp/… \| grep "n$" \| sort … \| tail -n 3` | сортировка по 5-му столбцу (размер) числами по убыванию |
| 4.6 | `ls -l… scizor 2>&1` | ключи для «по возрастанию размера»: `-S` и `-r` |

Файлы для ошибок в `/tmp` называй уникально, чтобы не пересечься с другими студентами: `/tmp/s561306_err_4_1` и так далее.

<details><summary>Что должно получиться (проверено)</summary>

- **4.1**: на экране пусто, а в файле ошибок `wc: chinchou/*: No such file or directory`. У `chinchou` нет права r, поэтому shell не может раскрыть `*`. Это нормальный результат по заданию, но на защите тебя спросят «почему». Вариант «с результатом»: временно `chmod u+r chinchou`, выполнить, вернуть. Тогда увидишь числа символов для `drapion` и `psyduck`. Лучше покажи в отчёте **оба** варианта.
- **4.2**: попадут строки с `pidgeotto` (сама папка и заголовок `./pansear/pidgeotto:`), а в файл ошибок уйдут `Permission denied` для закрытых каталогов.
- **4.3**: среди подходящих файлов только `scizor/wynaut`. Для каталогов на `t` (`furret`, `jellicent`, `unfezant`) придут сообщения `Is a directory`, они по заданию идут в stdout.
- **4.4**: вывод **пустой**. В `zoroark` нет латинского «ce», а в «Способности» буква «с» кириллическая. Так и должно быть, это можно объяснить на защите.
- **4.5**: три строки, `bagon`, `cranidosbagon` (у них одинаковый размер, это жёсткие ссылки на один файл) и `raltsbagon -> ../bagon`.
- **4.6**: сначала файлы от меньшего к большему, в конце каталоги (4096 байт).
</details>

## Шаг 5. Удаление (≈20 мин)
Та же схема: команда → ошибка (если есть) → исправление.

| Что удалить | Ловушка |
|---|---|
| `bagon` | нет права w у файла, `rm` спросит подтверждение. Это нормально, но в скрипте лучше `rm -f` |
| `scizor/snover` | то же самое |
| `Copy_*` | удаляется **ссылка**, а не `pansear`. Без `-r`! |
| `pansear/cranidosbag*` | у `pansear` нет w |
| `pansear` целиком | внутри закрытые каталоги (`omastar`, копия `chinchou`), `rm -r` не сможет их прочитать |
| `chinchou/starmie` | `rmdir`: папка пустая, а у `chinchou` есть w и x для владельца |

<details><summary>Подсказка</summary>

```bash
chmod u+w pansear
rm -f pansear/cranidosbag*
chmod -R u+rwx pansear     # открыть всё внутри, иначе rm -r не пройдёт
rm -r pansear
```
После `rm Copy_*` проверь, что `pansear` ещё на месте. Так ты увидишь разницу между удалением ссылки и удалением папки.
</details>
