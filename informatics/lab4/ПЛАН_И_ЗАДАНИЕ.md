## Шаг 1. Обязательное: парсер INI (Task1)

Цель: функция `parse_ini(text)` получает **строку** с содержимым файла и возвращает **словарь**:
```python
{'schedule': {'group': 'P3117', 'title': 'Расписание: вторник и пятница'},
 'tuesday': {'name': 'Вторник',
             'lesson_1': {'time': '08:10', 'subject': 'Линейная алгебра', ...},
             'lesson_2': {...}},
 'friday': {...}}
```
Это и есть «бинарный объект» из задания: структура данных в памяти программы, а не текст. Теория §2.

Нельзя: `re`, `configparser`, `json` и любые библиотеки разбора. Можно: обычный Python (`str`, `dict`, циклы, `open()` для чтения файла).

**Шаги.**
1. Выпиши грамматику INI в БНФ (теория §9). Она пойдёт в отчёт и на защиту.
2. Сделай класс `IniParser` с полями `text` и `pos` и методами-«глазами»: `peek()` (какой символ сейчас, не сдвигаясь), `advance()` (взять символ и сдвинуться), `skip_spaces()`. Теория §10.
3. На каждое правило грамматики по методу: `parse_file`, `parse_section`, `parse_pair`, `parse_value`, `parse_quoted`, `skip_comment`. Это и есть **рекурсивный спуск**.
4. В `parse_file` цикл до конца текста: смотришь на первый значимый символ строки и решаешь, какое правило применить.
5. Имя секции с точками превращаешь во вложенные словари.
6. Ошибки синтаксиса не глотай: `raise SyntaxError(...)` с номером строки.
7. Тесты, как в ЛР3: 5+ маленьких INI-строк с ответом, посчитанным вручную, и печать OK/FAIL.

<details><summary>Подсказка 1: каркас класса</summary>

```python
class IniParser:
    def __init__(self, text):
        self.text = text
        self.pos = 0
        self.line = 1

    def peek(self):
        if self.pos < len(self.text):
            return self.text[self.pos]
        return ''          # '' = конец текста

    def advance(self):
        ch = self.peek()
        self.pos += 1
        if ch == '\n':
            self.line += 1
        return ch
```
</details>

<details><summary>Подсказка 2: как выбрать правило</summary>

После `skip_spaces()` смотришь на `peek()`:
- `'\n'` или `'\r'` → пустая строка, просто `advance()`;
- `';'` или `'#'` → комментарий, пропустить до конца строки;
- `'['` → секция;
- `''` → конец файла, выход из цикла;
- всё остальное → пара `ключ = значение`.

Ровно так грамматика и записана: `<line> ::= <empty> | <comment> | <section> | <pair>`. Первый символ однозначно говорит, какая ветка, поэтому парсеру не нужно «откатываться» назад. Это называется LL(1).
</details>

<details><summary>Подсказка 3: вложенные секции</summary>

Держи `root = {}` и «текущий словарь» `current`. Для `[tuesday.lesson_1]`:
```python
node = root
for part in name.split('.'):
    node = node.setdefault(part.strip(), {})
current = node
```
`setdefault` возвращает существующий словарь или создаёт новый. Пары после секции кладёшь в `current[key] = value`.
</details>

<details><summary>Подсказка 4: значения</summary>

- Начинается с `"` → строка в кавычках, читаешь до закрывающей `"`. Внутри `\"` — это кавычка, а не конец строки. `;` внутри кавычек — часть текста, а не комментарий.
- Иначе читаешь до конца строки и делаешь `strip()`.
- Типы (по желанию, но красиво для HCL): `true`/`false` → `bool`, только цифры → `int`, остальное → `str`. Проверка «только цифры» без регулярки: `all('0' <= c <= '9' for c in raw)`.

⚠️ Номер аудитории `2316` тогда станет числом. Если хочешь, чтобы аудитории оставались строками, пиши их в кавычках: `room = "2316"`. Реши и объясни на защите.
</details>

**Вопросы, которые стоит решить и уметь объяснить:**
- Комментарий в конце строки (`time = 08:10 ; первая пара`) поддерживаешь или нет? В INI нет единого стандарта. Проще: комментарий только с начала строки.
- Повторный ключ в секции: последний перезаписывает первый.
- Пробелы вокруг `=` и в начале строки игнорируются.
- Windows-переводы строк `\r\n`: `\r` должен уходить при `strip()`.

**Идеи для тестов:** пустой текст → `{}`; одна секция с одной парой; вложенная секция `[a.b]`; комментарии `;` и `#`; значение в кавычках с `;` внутри; `true` и число; ошибка: секция без `]`.

**Шаги.**

3. `bool` → `true`/`false` (без кавычек!). `int` → как есть. `str` → в кавычках с экранированием.
4. Отступ: `'  ' * indent`.
5. Запиши результат в `schedule.hcl`.

<details><summary>Подсказка: экранирование строк</summary>

Внутри HCL-строки нужно экранировать `\` → `\\` и `"` → `\"`. Ещё одна ловушка HCL: `${` внутри строки — это вставка выражения (интерполяция). Чтобы написать её буквально, пишут `$${`. В расписании этого не будет, но на защите про это могут спросить.

⚠️ Порядок проверок: `isinstance(v, bool)` ставь **раньше** `isinstance(v, int)`, потому что в Python `True` тоже `int`.

## Шаг 3. Доп. 2: библиотеки (Task3)

| Шаг | Библиотека | Установка |
|---|---|---|
| INI → словарь | `configparser` | встроенная |
| словарь → HCL | `python-hcl2` (`import hcl2`) | `pip install python-hcl2` в `.venv` PyCharm |

Регулярки здесь тоже нельзя (сам их не пиши; что внутри библиотек, не важно).

Что выяснится при сравнении (я проверил на версии python-hcl2 8.1.4):
1. `configparser` **не понимает вложенность**: секция `tuesday.lesson_1` для него просто имя с точкой. Дерево придётся собрать вручную, как в подсказке 3.
2. Все значения у `configparser` — **строки**: `2` и `false` останутся `"2"` и `"false"`. У твоего парсера там `int` и `bool`.
3. `configparser` **не снимает кавычки**: `"Расписание"` останется вместе с кавычками.
4. По умолчанию `configparser` переводит ключи в **нижний регистр**. Отключается так: `cp.optionxform = str`.
5. `hcl2.dumps` пишет строки **без кавычек**, если сам их не добавишь: строку надо передать как `'"Алгебра"'`. Блок нужно передать как список из одного словаря с меткой `'__is_block__': True`, иначе получится `tuesday = { ... }` (это объект, а не блок).

Всё это — материал для раздела «сравнение» в отчёте (пункт 9c задания). Сравни три файла: `schedule.hcl` от твоего кода, от библиотек, и отличия по пунктам выше.

<details><summary>Подсказка: как подготовить словарь для hcl2.dumps</summary>

```python
def for_hcl2(d):
    out = {}
    for k, v in d.items():
        if isinstance(v, dict):
            out[k] = [dict(for_hcl2(v), __is_block__=True)]
        elif isinstance(v, str):
            out[k] = '"' + v.replace('\\', '\\\\').replace('"', '\\"') + '"'
        else:
            out[k] = v
    return out

text = hcl2.dumps(for_hcl2(tree))
```
</details>

## Шаг 4. Доп. 3: словарь → XML (Task4)

Та же рекурсия, что в Task2, только другой синтаксис (теория §7):
```xml
<?xml version="1.0" encoding="UTF-8"?>
<schedule_file>
  <schedule>
    <group>P3117</group>
  </schedule>
  <tuesday>
    <lesson_1>
      <time>08:10</time>
    </lesson_1>
  </tuesday>
</schedule_file>
```
1. У XML должен быть **один корневой элемент**, поэтому всё оборачиваем в `<schedule_file>`.
2. Словарь → `<ключ>` … `</ключ>` с рекурсией внутри. Значение → `<ключ>текст</ключ>`.
3. Экранирование текста: `&` → `&amp;` (**первым!**), `<` → `&lt;`, `>` → `&gt;`.
4. Имя тега не может начинаться с цифры, поэтому `lesson_1`, а не `1`.
5. Проверка: открой `schedule.xml` в браузере. Если XML сломан, браузер покажет ошибку.
