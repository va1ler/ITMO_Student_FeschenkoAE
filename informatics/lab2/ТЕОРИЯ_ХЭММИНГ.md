# Код Хэмминга: теория и решение варианта 6

## Зачем это нужно
При передаче данных биты иногда «переворачиваются» (0→1 или 1→0) из-за помех. Код Хэмминга добавляет к данным **проверочные биты**, по которым получатель может **найти и исправить одну ошибку**.

- **i** — информационные биты, то есть сами данные.
- **r** — проверочные биты (контроль чётности).
- Код (7;4): всего 7 бит, из них 4 информационных и 3 проверочных.
- Код (15;11): всего 15 бит, из них 11 информационных и 4 проверочных.

## Где стоят проверочные биты
Проверочные биты стоят на позициях-**степенях двойки**: 1, 2, 4, 8… Все остальные позиции информационные.
```
позиция: 1  2  3  4  5  6  7
бит:     r1 r2 i1 r3 i2 i3 i4
```

## Кто кого проверяет
Каждый бит проверяется теми проверочными битами, из которых складывается номер его позиции в двоичной записи:
- 3 = 1 + 2 → позицию 3 (i1) проверяют r1 и r2;
- 5 = 1 + 4 → i2 проверяют r1 и r3;
- 6 = 2 + 4 → i3 проверяют r2 и r3;
- 7 = 1 + 2 + 4 → i4 проверяют все три.

Отсюда три группы для (7;4):
| Проверка | Позиции | Биты |
|---|---|---|
| s1 | 1, 3, 5, 7 | r1, i1, i2, i4 |
| s2 | 2, 3, 6, 7 | r2, i1, i3, i4 |
| s3 | 4, 5, 6, 7 | r3, i2, i3, i4 |

`⊕` — сложение по модулю 2 (XOR): 0⊕0=0, 1⊕0=1, 1⊕1=0. Проще говоря, s = 1, если единиц в группе **нечётное** число.

## Как декодировать
1. Считаешь s1, s2, s3 по таблице.
2. Складываешь их в **синдром**: номер ошибочной позиции = s1·1 + s2·2 + s3·4.
3. Синдром 0 — ошибок нет. Иначе переворачиваешь бит на этой позиции.
4. Правильное сообщение — это исправленные **информационные** биты `i1 i2 i3 i4` (позиции 3, 5, 6, 7).

### Пример (не из твоего варианта)
Принято `1 0 1 1 0 0 1` (r1 r2 i1 r3 i2 i3 i4):
- s1 = r1⊕i1⊕i2⊕i4 = 1⊕1⊕0⊕1 = 1
- s2 = r2⊕i1⊕i3⊕i4 = 0⊕1⊕0⊕1 = 0
- s3 = r3⊕i2⊕i3⊕i4 = 1⊕0⊕0⊕1 = 0
- синдром = 1·1 + 0·2 + 0·4 = 1 → ошибка в r1, то есть в проверочном бите. Данные `i1 i2 i3 i4` = `1 0 0 1` верны.

## Схема декодирования (для отчёта)
В отчёте нужна картинка. Обычно рисуют **круги Эйлера (диаграмму Венна)**: три пересекающихся круга s1, s2, s3, в зонах пересечения стоят биты. Второй вариант — таблица «бит × проверка» с отметками. Для (15;11) кругов четыре, либо используют таблицу. Рисовать можно в draw.io (бесплатно, в браузере). Когда дойдём до отчёта, могу нарисовать схему сам.

## Код (15;11)
Всё то же самое, но позиций 15 и проверочных битов 4 (позиции 1, 2, 4, 8):
| Проверка | Позиции |
|---|---|
| s1 | 1, 3, 5, 7, 9, 11, 13, 15 (нечётные) |
| s2 | 2, 3, 6, 7, 10, 11, 14, 15 |
| s3 | 4, 5, 6, 7, 12, 13, 14, 15 |
| s4 | 8, 9, 10, 11, 12, 13, 14, 15 |

Синдром = s1 + 2·s2 + 4·s3 + 8·s4.

## Сколько нужно проверочных битов (пункт 8)
Для i информационных битов нужно минимальное r такое, что **2^r ≥ i + r + 1**. Коэффициент избыточности **k = r / (i + r)**, то есть доля «служебных» битов во всём сообщении.

<summary>Ответ: пункт 8</summary>

29 + 41 + 63 + 85 + 7 = 225; 225 × 4 = **900 информационных битов**.
r = 9: 2⁹ = 512 < 900 + 9 + 1 ✗; r = 10: 2¹⁰ = 1024 ≥ 900 + 10 + 1 = 911 ✓ → **r = 10**.
k = 10 / (900 + 10) = 10 / 910 ≈ **0,011** (≈ 1,1%).
