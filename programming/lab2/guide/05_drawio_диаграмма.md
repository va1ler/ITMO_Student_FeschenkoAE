# ЛР2 — диаграмма классов в draw.io

[← план лабы](./04_план_лабы.md)

Диаграмма рисуется **после того, как код готов**: она описывает то, что реально написано.

## 1. Минимум UML, который нужно знать (и на защите тоже)

**Класс** — прямоугольник из трёх частей:
```
┌──────────────────────────────┐
│           Golurk             │  ← имя (курсив или «abstract» — абстрактный класс)
├──────────────────────────────┤
│                              │  ← поля: видимость имя: Тип
├──────────────────────────────┤
│ + Golurk(name: String,       │  ← методы: видимость имя(параметры): ТипВозврата
│          level: int)         │
└──────────────────────────────┘
```

**Видимость:** `+` public · `-` private · `#` protected · `~` package-private.
**static** — подчёркнуто. **abstract** — курсив или `«abstract»`. **final** — `{leaf}` или `«final»` под именем.

**Связи:**
| Связь | Как выглядит | Смысл | У нас |
|---|---|---|---|
| Наследование (генерализация) | сплошная линия, **пустой треугольник** у предка | «является» | `Golurk → Golett → Pokemon`, `Thunder → SpecialMove` |
| Агрегация | ромб **пустой** у целого | «имеет», часть живёт и сама | `Pokemon ◇— Move` (0..4) |
| Композиция | ромб **закрашенный** у целого | часть не живёт без целого | — |
| Зависимость | **пунктир** со стрелкой | «использует» | `Main ┄> Battle`, `Main ┄> покемоны` |

## 2. Что должно быть на диаграмме

- **Библиотечные** (можно серым и без деталей): `Pokemon`, `Move` «abstract», `DamageMove` «abstract», `PhysicalMove`, `SpecialMove`, `StatusMove`, `Battle`.
- **Твои покемоны** (6): с конструктором.
- **Твои атаки** (12): с конструктором и переопределёнными методами (`# describe(): String`, `# applyOppEffects(p: Pokemon): void` и т. п.).
- **`Main`** с `+ main(args: String[]): void` (подчёркнуто — static).
- Пакеты можно обвести рамками: `lab2`, `pokemons`, `moves`, `ru.ifmo.se.pokemon`.
- У final-классов — пометка `«final»`.

Компоновка, чтобы не было каши: **сверху** библиотека, **слева внизу** покемоны (цепочки столбиками), **справа внизу** атаки под тремя своими предками.

## 3. draw.io desktop по шагам

1. **File → New → Blank Diagram** → Create. Сохрани сразу: **File → Save as** → `programming/lab2/report/диаграмма_классов.drawio`.
2. Слева панель фигур. Внизу **+ More Shapes** → включи **UML** → Apply.
3. В разделе UML перетащи фигуру **Class** (прямоугольник с заголовком и строками).
4. Двойной клик по заголовку — имя класса. Двойной клик по строке — поле/метод. Новая строка: выдели строку → **Ctrl/Cmd+Enter** (дублирует). Пустую часть полей можно удалить.
5. Курсив для абстрактного: выдели заголовок → панель справа **Text** → *I*.
6. **Стрелка наследования:** наведи на класс-потомок, потяни синюю стрелку к предку. Потом справа во вкладке **Style** у линии: конец (*Line end*) — **пустой треугольник** (`block`, без заливки). Проще: в разделе UML есть готовая связь **Inheritance** / **Extends** — перетащи её и прицепи концы.
7. Пунктир для зависимости: вкладка **Style** → *Pattern* → dashed, конец — открытая стрелка.
8. Выравнивание: выдели несколько классов → **Arrange → Align** / **Distribute**. Сетка помогает: **View → Grid**.
9. Копирование однотипных атак: выдели готовую атаку → **Cmd+D** (дубликат), меняй текст.
10. **Экспорт для отчёта:** **File → Export as → PNG**, Zoom **200%**, Border **10**, галочка *Transparent background* **снята**. Сохрани `диаграмма_классов.png` рядом.

## 4. Упражнение (до настоящей диаграммы, 15 мин)

Нарисуй диаграмму для примера из пособия (`pract2.pdf`, версия 7): `Shape` «abstract» с `+ printDescription(): void`, `getArea(): double`, `getPerimeter(): double` (курсивом — абстрактные), три наследника `Rectangle`, `Circle`, `Triangle` с private-полями и `Main`, который их использует. Скинь мне PNG — проверю нотацию.
