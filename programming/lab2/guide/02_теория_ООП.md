## §1. Что такое ООП и зачем оно

**Парадигма** — способ думать о программе.
- В **процедурном** стиле (как в ЛР1) программа — это данные + функции, которые их обрабатывают. Данные и функции живут отдельно.
- В **ООП** программа — это набор **объектов**, которые взаимодействуют. Объект = **состояние** (данные, поля) + **поведение** (методы), упакованные вместе.

Пример из пособия (`pract2.pdf`): ширины и высоты прямоугольников в двух отдельных массивах легко рассинхронизировать. Если же сделать класс `Rectangle` с полями `width` и `height`, данные одного прямоугольника всегда вместе, а считать площадь умеет сам прямоугольник: `r.getArea()`.

**Четыре кита ООП** (часто спрашивают все четыре, а не три):

| Принцип | Одной фразой | В нашей лабе |
|---|---|---|
| **Абстракция** | выделяем в объекте только важное для задачи | покемон = тип + 6 характеристик + атаки; цвет глаз нам не нужен |
| **Инкапсуляция** | прячем внутреннее устройство, наружу даём только нужные методы | поля `Pokemon` закрыты, менять их можно только через `setStats`, `setType` |
| **Наследование** | новый класс получает поля и методы существующего и дополняет их | `Golurk extends Golett extends Pokemon` |
| **Полиморфизм** | один интерфейс — разные реализации; вызывается версия метода **реального** класса объекта | `Battle` вызывает у любого покемона `attack`, а каждая атака сама решает, что делать |

Ключевая мысль для защиты: **ООП нужно, чтобы программу было легко расширять и сложно сломать.** Добавить нового покемона = написать новый класс, не трогая `Battle`.

## §2. Класс и объект

**Класс** — это описание (чертёж, тип данных). **Объект** (экземпляр) — конкретная вещь, созданная по этому чертежу.

```java
public class Cat {          // класс — чертёж
    String name;            // поле
    int age;                // поле

    void meow() {           // метод
        System.out.println(name + ": мяу");
    }
}

Cat a = new Cat();          // объект №1
Cat b = new Cat();          // объект №2 — другой, со своими полями
a.name = "Барсик";
b.name = "Мурзик";
a.meow();                   // Барсик: мяу
```

Важно:
- Класс в Java — это ещё и **тип**: `Cat a` означает «переменная `a` типа Cat».
- Переменная `a` хранит **не сам объект, а ссылку** на него (адрес в куче). `Cat c = a;` — теперь `c` и `a` указывают на **один** объект.
- Все классы неявно наследуются от `java.lang.Object`, поэтому у любого объекта есть `toString()`, `equals()`, `hashCode()`, `getClass()`.
- Один `public` класс → один файл с тем же именем: `public class Cat` живёт в `Cat.java`.

**Типы в Java делятся на два мира:**
| Примитивные | Ссылочные |
|---|---|
| `int`, `double`, `boolean`, `char`, `long`, `byte`, `short`, `float` | классы, массивы, интерфейсы, enum |
| хранят **значение** | хранят **ссылку** на объект |
| по умолчанию 0 / false | по умолчанию `null` |
| сравнивать `==` | `==` сравнивает ссылки (тот же объект?), содержимое — `equals()` |

<details><summary>Упражнение 2</summary>

Что выведет?
```java
Cat a = new Cat(); a.name = "A";
Cat b = a;
b.name = "B";
System.out.println(a.name);
```
**Ответ:** `B`. `a` и `b` ссылаются на один объект.
</details>

## §3. Члены класса: поля, методы, конструкторы

### Поля
Переменные, объявленные **в классе, вне методов**. Описывают состояние объекта.
- Поля получают значения **по умолчанию** (`0`, `false`, `null`), локальные переменные — нет (без инициализации — ошибка компиляции).

### Методы
```java
модификаторы ТипВозврата имя(параметры) { тело }
public       double      getArea()      { return width * height; }
```
- `void` — ничего не возвращает.
- **Сигнатура** метода = имя + типы параметров (тип возврата в сигнатуру **не входит**).
- **Перегрузка (overloading)** — несколько методов с одним именем, но разными параметрами в **одном** классе. Выбор — при компиляции.
  ```java
  void print(int x) {...}
  void print(String s) {...}
  ```
- **Переопределение (overriding)** — потомок пишет **свою версию** метода предка с той же сигнатурой. Выбор — во время выполнения (это и есть полиморфизм, §7). Помечаем `@Override` — компилятор проверит, что мы действительно что-то переопределяем, а не опечатались.
- Аргументы в Java передаются **по значению**. Для объекта копируется **ссылка**: метод может поменять поля объекта, но не может заменить сам объект у вызывающего.

### Конструкторы
Специальный «метод», который вызывается при `new` и инициализирует объект.
- Имя = имя класса, **нет типа возврата** (даже `void`).
- Если не написать ни одного — компилятор добавит **конструктор по умолчанию** без параметров. Если написать хоть один — дефолтного уже не будет.
- Конструкторы можно перегружать.
- `this(...)` — вызвать другой конструктор этого же класса; `super(...)` — конструктор родителя. Любой из них — **только первой строкой**.

```java
public class Rectangle {
    private double width, height;

    public Rectangle(double width, double height) {
        this.width = width;      // this.width — поле, width — параметр
        this.height = height;
    }
    public Rectangle(double side) {
        this(side, side);        // квадрат: зовём первый конструктор
    }
}
```

**`this`** — ссылка на текущий объект. Нужна, когда параметр «затеняет» поле с тем же именем, и для вызова `this(...)`.

<details><summary>Упражнение 3</summary>

1. Почему не скомпилируется `class A { A(int x){} }  ...  new A();`?
2. Чем перегрузка отличается от переопределения?

**Ответы:** 1) Написан конструктор с параметром → дефолтный не создаётся, а `A()` не существует. 2) Перегрузка — разные параметры, один класс, выбор при компиляции; переопределение — та же сигнатура в потомке, выбор при выполнении по реальному классу объекта.
</details>

## §4. Модификаторы доступа и инкапсуляция

| Модификатор | Свой класс | Пакет | Потомок в другом пакете | Все |
|---|---|---|---|---|
| `private` | ✅ | ❌ | ❌ | ❌ |
| *(нет, package-private)* | ✅ | ✅ | ❌ | ❌ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| `public` | ✅ | ✅ | ✅ | ✅ |

Запомнить: **слева направо — шире**. `protected` = «пакет + наследники».

Для **классов верхнего уровня** допустимы только `public` или ничего.

**Инкапсуляция** на практике:
```java
public class Account {
    private double balance;                 // снаружи не тронуть

    public double getBalance() { return balance; }     // геттер
    public void deposit(double sum) {                  // контролируемое изменение
        if (sum <= 0) throw new IllegalArgumentException("сумма > 0");
        balance += sum;
    }
}
```
Смысл: объект **сам следит за корректностью** своего состояния. Никто не сделает `balance = -1000`.

Это прямо видно в `Pokemon.jar`: у `Pokemon` методы `setType`, `setMove`, `addMove` — **`protected`**. Вызвать `p.addMove(...)` из `Main` нельзя, а из конструктора наследника — можно. Поэтому атаки назначаются **внутри классов покемонов**.

⚠️ Правило переопределения: потомок **может расширить** доступ (`protected` → `public`), но **не может сузить** (`public` → `private` — ошибка).

<details><summary>Упражнение 4</summary>

В `Move` метод `describe()` — `protected`. Можно ли в потомке написать `@Override public String describe()`? А `private String describe()`?

**Ответ:** `public` — можно (расширение), `private` — нельзя (сужение).
</details>

## §5. Создание и инициализация объектов. Вызов методов

```java
Golurk g = new Golurk("Голем", 43);
```
Что происходит по шагам:
1. Если класс ещё не загружен — JVM загружает `Golurk` **и всех предков** (`Golett`, `Pokemon`, `Object`), выполняет их **static-инициализацию** (один раз за программу), от предка к потомку.
2. В **куче (heap)** выделяется память под объект, все поля = значения по умолчанию.
3. Вызывается конструктор `Golurk(...)`. Его первая строка — `super(name, level)` → конструктор `Golett` → его `super(...)` → `Pokemon` → `Object`.
4. Цепочка «разматывается» обратно: сначала отрабатывают инициализаторы полей и тело конструктора **`Object`**, потом **`Pokemon`**, потом **`Golett`**, и последним — тело **`Golurk`**.
5. `new` возвращает ссылку, она кладётся в локальную переменную `g` (сама переменная — в **стеке** метода).

**Порядок инициализации внутри одного класса:** static-поля и static-блоки (при загрузке) → при каждом `new`: поля экземпляра и `{ }`-блоки по порядку → тело конструктора.

Если в конструкторе потомка **нет** явного `super(...)`, компилятор вставит `super()` без параметров. Если у родителя такого нет — ошибка компиляции. Поэтому в лабе первая строка конструктора покемона — всегда `super(name, level);`.

**Вызов методов:**
- метод объекта: `ссылка.метод(аргументы)` — `g.getHP()`;
- статический метод: `ИмяКласса.метод()` — `Math.random()`, `Effect.paralyze(p)`;
- внутри класса свой метод можно звать без префикса (`getArea()` = `this.getArea()`);
- `super.метод()` — вызвать **версию родителя** (полезно, когда переопределяешь и хочешь дополнить, а не заменить).

Если ссылка `null` — вызов метода кинет **`NullPointerException`**.

**Сборка мусора (GC):** объекты не удаляются вручную. Когда на объект не остаётся ни одной ссылки, сборщик мусора когда-нибудь освободит память.

<details><summary>Упражнение 5</summary>

```java
class A { A() { System.out.print("A "); } }
class B extends A { B() { System.out.print("B "); } }
class C extends B { C() { super(); System.out.print("C "); } }
new C();
```
**Ответ:** `A B C ` — тела конструкторов выполняются от предка к потомку.
</details>

## §6. Наследование

```java
class Golett extends Pokemon { ... }   // Golett — потомок (подкласс), Pokemon — предок (суперкласс)
```
- Потомок получает все **не-private** поля и методы предка, может добавить свои и переопределить унаследованные.
- В Java **одиночное наследование классов**: `extends` только одного класса. (Множественное — только через интерфейсы.)
- Отношение «**является**» (is-a): Golurk **является** Golett, Golett **является** Pokemon. Поэтому `Pokemon p = new Golurk(...)` — законно (**восходящее преобразование, upcasting**, автоматическое).
- Конструкторы **не наследуются**, их вызывают через `super(...)`.
- `private`-члены предка в потомке **есть** (они часть объекта), но **недоступны** напрямую.

**Как это работает в лабе:**
```java
public class Flabebe extends Pokemon {
    public Flabebe(String name, int level) {
        super(name, level);
        setType(Type.FAIRY);
        setStats(...);
        setMove(new DazzlingGleam(), new Facade());
    }
}
public class Floette extends Flabebe {
    public Floette(String name, int level) {
        super(name, level);   // тут Flabebe уже поставит тип и 2 атаки
        setStats(...);        // свои характеристики
        addMove(new VineWhip()); // + новая атака
    }
}
```
Тип у всей цепочки FAIRY, поэтому в `Floette` заново ставить не нужно (у Golett/Golurk аналогично GROUND+GHOST).

**Композиция vs наследование** (вопрос «на подумать»): наследование — «является» (Golurk **является** покемоном), композиция — «имеет» (покемон **имеет** атаки: внутри `Pokemon` лежит список объектов `Move`). Правило хорошего тона: если не уверен — композиция.

## §7. Полиморфизм

**Полиморфизм подтипов**: переменная типа предка может ссылаться на объект потомка, и при вызове метода выполнится версия **реального класса объекта**. Это называется **динамическое (позднее) связывание**, dynamic dispatch.

```java
Move m = new Thunder();   // тип переменной Move, реальный объект Thunder
m.describe();             // вызовется Thunder.describe()
```

Как это использует `Battle`: он хранит покемонов как `Pokemon`, атаки как `Move`, и ничего не знает о твоих классах. Но когда он вызывает у атаки `attack(...)`, внутри дёргаются **твои** `applyOppEffects`, `describe`, `checkAccuracy`. Библиотека 2018 года вызывает код, написанный тобой в 2026, — вот это и есть полиморфизм. Хороший пример для защиты.

Что важно знать:
- **Компилятор** смотрит на тип **переменной**: какие методы вообще можно вызвать. **JVM** при выполнении смотрит на тип **объекта**: какую версию вызвать.
- Динамически выбираются только **переопределённые методы экземпляра**. `static`-методы, `private`-методы и **поля** не полиморфны.
- **Нисходящее преобразование (downcasting)** — явное: `Golurk g = (Golurk) p;`. Если `p` на самом деле не Golurk → `ClassCastException`. Проверка: `if (p instanceof Golurk) ...`.
- Виды полиморфизма для эрудиции: **ad-hoc** (перегрузка), **параметрический** (дженерики `List<T>`), **подтипов** (переопределение). На защите обычно ждут последний.

## §8. Абстрактные классы и интерфейсы

**Абстрактный класс** (`abstract class`) — нельзя создать объект (`new Move()` — ошибка), он задуман как общий предок.
- Может содержать **абстрактные методы** (без тела) — потомок **обязан** их реализовать или сам быть абстрактным.
- Может содержать обычные поля, конструкторы и методы с телом.

В библиотеке: `Move` и `DamageMove` — абстрактные. У `Move` абстрактный `attack(...)`, у `DamageMove` — `calcAttDefFactor(...)`. А `PhysicalMove`, `SpecialMove`, `StatusMove` уже обычные классы, их реализуют.

**Интерфейс** (`interface`) — контракт «что умеет»: набор абстрактных методов (с Java 8 можно `default` и `static` методы с телом), полей нет (только константы). Класс может `implements` **сколько угодно** интерфейсов.

| | Абстрактный класс | Интерфейс |
|---|---|---|
| Наследование | один | много |
| Поля-состояние | да | нет (только `public static final`) |
| Конструктор | есть | нет |
| Смысл | «является разновидностью» | «умеет делать» |

`abstract` и `final` вместе на классе — **нельзя** (противоречие: «обязательно наследуй» и «наследовать нельзя»).

## §9. Области видимости переменных

**Область видимости (scope)** — участок кода, где имя переменной доступно. **Время жизни** — сколько существует сама переменная.

| Вид | Где объявлена | Видна | Живёт |
|---|---|---|---|
| **Поле экземпляра** | в классе, без `static` | во всём классе (снаружи — по модификатору доступа) | пока жив объект |
| **Статическое поле** | в классе, `static` | во всём классе | пока загружен класс (≈ всю программу) |
| **Параметр метода** | в скобках метода | во всём теле метода | пока выполняется метод |
| **Локальная переменная** | в теле метода | от объявления до `}` своего блока | до конца блока |
| **Переменная цикла/блока** | `for (int i...)`, внутри `{}` | только внутри блока | до конца блока |

```java
public class Demo {
    int x = 10;                 // поле
    void f(int y) {             // параметр
        int z = 5;              // локальная
        for (int i = 0; i < 3; i++) {   // i видна только в цикле
            int t = i * z;      // t только в теле цикла
        }
        // System.out.println(i);  — ошибка: i тут не видна
        int x = 1;              // ЗАТЕНЯЕТ поле x (shadowing)
        System.out.println(x);       // 1
        System.out.println(this.x);  // 10
    }
}
```
- В Java **нельзя** объявить локальную переменную с именем другой локальной из внешнего блока того же метода (в отличие от C++). А затенить поле — можно.
- Локальные переменные **не инициализируются** автоматически.
- Анонимные классы/лямбды могут использовать локальные переменные только если они `final` или **effectively final** (не меняются после присвоения).

## §10. `final` и `static`

### `final` — «больше нельзя менять»
| Где | Что значит | В лабе |
|---|---|---|
| **класс** | от класса нельзя наследоваться | все «листья»: Thundurus, Golurk, Florges и все 12 атак |
| **метод** | метод нельзя переопределить | в `Pokemon` почти все методы `final` — нельзя сломать логику боя |
| **поле** | значение присваивается ровно один раз (при объявлении или в конструкторе) | — |
| **локальная / параметр** | нельзя переприсвоить | — |

⚠️ `final` у ссылки запрещает **переприсвоить ссылку**, но **не** менять сам объект: `final int[] a = {1}; a[0] = 5;` — можно; `a = new int[2];` — нельзя.

Константа: `public static final double G = 9.81;` — имя КАПСОМ.

Примеры final-классов в JDK: `String`, `Math`, `Integer`. Зачем: безопасность и неизменяемость.

### `static` — «принадлежит классу, а не объекту»
| Где | Что значит |
|---|---|
| **поле** | одно на весь класс, общее для всех объектов (`Cat.count`) |
| **метод** | вызывается без объекта: `Math.sqrt(2)`; внутри **нет `this`**, нельзя напрямую обращаться к нестатическим полям/методам |
| **блок `static { }`** | выполняется один раз при загрузке класса |
| **вложенный класс** | не привязан к объекту внешнего класса |

```java
public class Cat {
    private static int count = 0;   // общий счётчик
    private final String name;      // у каждого свой, задаётся один раз
    public Cat(String name) { this.name = name; count++; }
    public static int getCount() { return count; }
}
```
Почему `main` статический: JVM запускает его **до создания каких-либо объектов**.

В лабе: `Effect.paralyze(p)`, `Math.random()` — статические вызовы.

<details><summary>Упражнение 10</summary>

1. Почему из `static void main` нельзя просто вызвать нестатический метод `foo()` того же класса?
2. Может ли `static`-метод быть переопределён?

**Ответы:** 1) У `static`-метода нет `this` — непонятно, у какого объекта вызывать `foo()`. Нужно `new Main().foo()`. 2) Нет: метод с той же сигнатурой в потомке **скрывает** (hiding), а не переопределяет, полиморфизма нет.
</details>

## §11. Пакеты и `import`

**Пакет** — пространство имён + папка. Решает конфликты имён (`java.util.List` и `java.awt.List`) и даёт уровень доступа «package-private».

- Объявление — **первая строка** файла: `package moves;`
- Пакет = **путь к папке**: класс `moves.Thunder` должен лежать в `moves/Thunder.java`, а скомпилированный — в `moves/Thunder.class`.
- **Полное имя** класса: `ru.ifmo.se.pokemon.Pokemon`. Пакеты именуют перевёрнутым доменом: `ru.ifmo.se`.
- Класс без `package` попадает в **безымянный пакет по умолчанию** (так было в ЛР1). Из именованного пакета его не импортировать — поэтому в ЛР2 всё раскладываем по пакетам.

**`import`** — просто сокращение, чтобы не писать полное имя. На скорость и размер программы **не влияет**, код не «подключает».
```java
import ru.ifmo.se.pokemon.Pokemon;   // один класс
import ru.ifmo.se.pokemon.*;         // все классы пакета (но НЕ подпакетов!)
import static java.lang.Math.PI;     // статический импорт: пишем просто PI
```
- `java.lang.*` (String, Math, System, Object) импортируется **автоматически**.
- Классы своего же пакета видны без импорта.
- `*` не импортирует подпакеты: `import ru.ifmo.*` не даст `ru.ifmo.se.pokemon.Pokemon`.

**Classpath (`-cp`)** — где JVM и `javac` ищут классы. Пакеты отвечают «как называется класс», classpath — «где лежит корень». Для лабы:
```
javac -cp Pokemon.jar:. -d out ...   # : — разделитель на macOS/Linux (на Windows ;)
java  -cp Pokemon.jar:out lab2.Main  # запускаем по ПОЛНОМУ имени класса
```
`-d out` — куда сложить `.class`, раскладывая по папкам пакетов.

**JAR** — zip-архив с `.class` и `META-INF/MANIFEST.MF`. Распаковывать `Pokemon.jar` не нужно: JVM читает классы прямо из архива, если он в classpath.

## §12. Сверху: `Object`, `toString`, `equals`, `enum`

- **`toString()`** — строковое представление; вызывается автоматически при `System.out.println(obj)` и `"..." + obj`. По умолчанию — `ИмяКласса@хеш`. В `Pokemon` он уже `final` и выводит вид и имя.
- **`equals()` / `hashCode()`** — логическое равенство. Если переопределяешь `equals`, переопредели и `hashCode` (иначе сломаются `HashMap`/`HashSet`).
- **`enum`** — класс с фиксированным набором объектов-констант. `Type.FIRE`, `Stat.SPEED`, `Status.PARALYZE` — это enum'ы библиотеки. Сравнивать можно через `==`.

<details><summary>10 вопросов, ответы внутри</summary>

1. Чем класс отличается от объекта? — Класс — описание/тип, объект — экземпляр в памяти, созданный `new`.
2. Что хранит переменная `Pokemon p`? — Ссылку на объект (или `null`).
3. Что будет, если в конструкторе потомка не написать `super(...)`? — Компилятор вставит `super()`; если у предка нет конструктора без параметров — ошибка.
4. Почему `setMove` нельзя вызвать из `Main`? — Он `protected`, а `Main` не потомок `Pokemon` и не в пакете `ru.ifmo.se.pokemon`.
5. Зачем атаки делать `final`? — Требование задания: класс без наследников должен быть защищён от наследования.
6. Можно ли `final`-метод перегрузить? — Да; нельзя только переопределить.
7. Почему `Battle` вызывает твой `describe()`, хотя ничего о нём не знает? — Позднее связывание: вызывается версия реального класса объекта.
8. Что делает `@Override`? — Просит компилятор проверить, что метод действительно переопределяет метод предка.
9. Что такое `-cp Pokemon.jar:.`? — Classpath: искать классы в архиве и в текущей папке.
10. Разница `import a.b.*` и `import a.b.C`? — Первое — все классы пакета `a.b` (без подпакетов), второе — один класс. Влияет только на сокращение имён.
</details>
